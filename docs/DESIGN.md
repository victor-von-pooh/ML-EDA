# 設計

ML-EDA の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) にある.

## 1. 役割と位置づけ

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「データの分析」の段階でライブラリを受け持つ. 画面は ML-Fathom.

機械学習に使うデータを読み込み, 探索的に分析し (EDA), 前処理をして, 学習 (ML-Found) にそのまま渡せる形に書き出す. 表, 時系列, 画像, 文, 点群のように形の違うデータを, 同じ考え方で扱う.

- GUI のアプリ (ML-Fathom) が必要とすること (読み込みの結果, 分析の結果, 気付き, 前処理の前と後) は, このライブラリが JSON にできる辞書で返す. 画面に固有のものは入れない
- 学習とモデルの組み立ては対象外. 書き出したデータセットは, ML-Found の学習スクリプトがこのライブラリで読み込んで使う
- **問題の設定との分け方**: 何を予測するか (目的の列), タスクの種類 (分類, 回帰など) は問題の設定の段階が決める. ただしデータの理解は目的が決まる前から始められるので, 読み込みと分析は目的無しで動く. 目的の列とタスクの種類は, 前処理と分割と書き出しのときに要るので, レシピに書き, 書き出すデータセットの説明に記録する. レシピは利用者が書くか, 問題の設定 (ML-Quest) の受け渡しから作る (ML-Fathom の「問題の設定から始める」. このライブラリは ML-Quest を読まない)
- 他の段階のライブラリのコードを前提にしない

## 2. 他のリポジトリとの約束

このライブラリが持つ約束. 他の段階の約束は読まない.

| 約束 | 持つか読むか | 版 | 使う側と中身 |
| --- | --- | --- | --- |
| 前処理のレシピ (YAML) | 持つ | `format_version` 1 | ML-Fathom, ML-Quest (雛形と書き戻し). 下の「前処理のレシピ」 |
| データセット (`dataset.yaml` と分割ごとのデータ) | 持つ | `format_version` 1 (列の正解), 2 (ファイルの組とまとまり) と 3 (版 2 に中身の手順を足したもの). 版 1 は `load_dataset`, 版 2 と 3 は `load_items` で読み, もう一方の版と知らない版は誤りで止まる | 学習のスクリプト (ML-Quest の骨組みを含む), ML-Found (`task_from_dataset` が版 2 の説明を読む), ML-Inference, ML-Fathom と ML-Provide (書き出しと見本. ML-Fathom はモデルの入力 `model_inputs` も見せる), ML-CreateArchitecture (`model_inputs` でモデルの定義の入力と出力をデータセットに合わせる). 下の「書き出し (学習との約束)」「書き出しの版 2」 |
| データの読み方 (`Data.source` の `loader` と `options`) | 持つ | 版を持たない (読み込みの名前と設定) | ML-Quest (問題の設定の `data` に残す), ML-Fathom. 下の「読み込み」 |
| 撮影の正規化の平行移動 (`shift`) | 持つ | データセットの版 2 に含む | 利用者の学習と推論のスクリプト (`normalize_capture` の `summary["shift"]`). 正規化した座標 = 元の座標 + shift. 元の座標に戻すには shift を引く. 下の「撮影と点群の対」. ML-Found の見本の値の決まり (`convention.shift`) は, 見本の一覧の版 2 でこれと同じ向き (ML-Found の `load_samples` は逆の向きの版 1 を版 2 の意味に写して返す) |

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 種類 (kind) | データの形. `table` (表), `timeseries` (時系列), `image` (画像), `text` (文), `pointcloud` (点群) |
| 読み込み (loader) | ファイルかディレクトリを, ある種類のデータとして読む部品. 拡張子と中身から, 使える読み込みを選ぶ |
| データ (`Data`) | 読み込んだ結果. 全ての種類で, pandas の `DataFrame` (`frame`) を中心に持つ |
| 気付き (finding) | 分析で見つけた, 学習の前に確かめた方がよいこと (欠損の多い列, ほぼ定数の列, リークの疑い, クラスの偏りなど). 重要度 (`warning`, `info`) と理由を持つ |
| レシピ (recipe) | 前処理の手順の並び. YAML に書き, 版を付ける |
| データセット (dataset) | 前処理をして分割したデータを, 学習用に書き出したディレクトリ |
| 項目 (entry) | 版 2 のデータセットの 1 件を作る, 名前を付けた入力か正解 (画像, 領域, 撮影, 点群など). 「書き出しの版 2」 |

## 4. データの形

全ての種類で, 中心は 1 つの `DataFrame` (`frame`). 分析と前処理の多くを, 種類に依らず pandas の同じ仕組みで行うため.

| 種類 | `frame` の 1 行 | 中身 |
| --- | --- | --- |
| `table` | 1 件 | 読み込んだ表そのもの |
| `timeseries` | 1 時点 | 表と同じ. 日時の列 (`time_column`) を持ち, 時刻の順に並べる |
| `image` | 1 枚の画像 | ファイルの場所 (`path`), ラベル (クラスごとのフォルダなら `label`), 幅, 高さ, チャンネル数, 大きさ (バイト), ファイルの中身の SHA-256 (`digest`. 同じ画像を見つけるため, 読み込みで全てのバイトを読む. 大きなフォルダでは読み込みの設定 `digest: false` で省ける. 読み込みの種類の設定の一覧にも出し, 画面からの文字 (`false`, `0`, `no`) も読む) など. 画素は `load_item` で必要なときだけ読む |
| `text` | 1 つの文 | 文 (`text`), ラベル (あれば), 文字数, 語の数など |
| `pointcloud` | 1 つの点群 | ファイルの場所, 点の数, 範囲, 属性 (色, 法線) の有無など. 点は `load_item` で読む |
| `capture` | 1 回の多視点の撮影 | 撮影のディレクトリの場所, 枚数, 追跡できた枚数, 画像の大きさ, 深度の有効率と信頼度, 撮影距離, 周回の最も大きい隙間など. 各枚の画像と姿勢と深度の場所は `load_item` で読む |

`Data` が持つもの.

- `kind`: 種類
- `frame`: 上の `DataFrame`
- `source`: 読み込んだ場所, 読み込み (`loader`) の名前, 読み込みの設定
- `roles`: 列の役割 (`target` 目的の列, `time` 日時の列, `id` 識別子の列, `text` 文の列, `path` ファイルの場所の列). 推定するか, 利用者が指定する
- `load_item(index)`: 画像, 点群などの 1 件の中身を読む関数 (表には無い)

大きなデータは, 分析では先頭ではなく無作為に選んだ見本 (既定 10 万行. 画像などは 2000 件) を使い, 見本で計算したことを結果に書く. 時系列は間隔を保つように等間隔に間引き, 時刻の間隔と抜けは間引く前の全体で求める.

読み込みでは, 日付の区切り (`-`, `/`, `:`, `年`) を含む値の列だけを日時の候補にする (カンマ付きの数などを日時と取り違えないように). `2024年1月3日` の書き方も日時にし, 書き方の混ざった列も読む. `1,234` の形の桁区切りの数と, 前に通貨の記号 (`¥$€£`), 後に決まった単位 (円, %, 個, kg など) の付いた数 (読めた値が全て同じ単位) は数にする (全角の数字も. マイナスは記号の前でも後でも. 単位の違う値の混ざる列, 0 で始まる値 (001件), 型番のような他の文字の付いた値は数にしない. % や 万円 は換算せず, 書いた数のまま). 日時の列の値が重なっていて, 別の列 (文字か整数, 2 から 10000 種類. 1 つの値あたり平均 10 行以上) と組にすると重ならず, その組の半分以上が埋まり, 1 割以上の時刻に 2 つ以上の値が並ぶ (店ごとの売上のような複数の系列. 注文の表の顧客のようにまばらなものと, 時刻が行ごとに違い, 重複した行だけで時刻が重なるレビューのラベルのようなものは除く) 場合は時系列とし, その列を役割 `series` に記録する. 分析では間隔と自己相関を最も長い系列で求め (`series_by`, `series_count`. 見本で分析する場合も, 間引く前の最も長い系列で), 間引く場合は時刻の値で間引いて全ての系列を残す. 順位の列 (1 位から N 位) のように, 同じ時刻に値が並ぶ数の列も系列と判定されうる (読み方で表として読むか, 時刻の列を選び直す). 列の名前は文字にそろえ, 重なる名前には番号を付ける (`name.1`).

## 5. 読み込み

読み込みは登録簿に集める (ML-ModelControl の部品の登録簿と同じ考え方). 1 つの読み込みは次を持つ.

- 名前 (`csv`, `image_folder` など), 種類, 扱う拡張子
- `sniff(path)`: その場所を読めるかと, その確からしさ (0 から 1) を返す. 拡張子だけでなく中身 (先頭の数行, ディレクトリの構成) も見る
- `load(path, **options)`: `Data` を返す
- 設定 (区切り文字, 文字コード, ヘッダーの行, 日時の列など) の説明と既定値

`load_data(path, loader=None, **options)` は, 指定が無ければ全ての読み込みの `sniff` で一番確からしいものを選ぶ. `detect(path)` は候補を確からしさの順に返す (GUI で選び直せるように).

| 読み込み | 種類 | 対象 |
| --- | --- | --- |
| `csv` | table / timeseries | `.csv`, `.tsv`, `.txt` (区切り文字と文字コードを推定) |
| `json` | table / timeseries | `.json` (レコードの配列, 列の辞書, 入れ子は平らにする), `.jsonl` / `.ndjson` |
| `parquet` | table / timeseries | `.parquet` (pyarrow が要る) |
| `excel` | table / timeseries | `.xlsx` (openpyxl が要る) |
| `npy` | table / pointcloud | `.npy`, `.npz` (2 次元の配列は表, (N, 3 以上) で名前が点群らしいものは点群) |
| `image_folder` | image | 画像のディレクトリ (`<クラス>/<画像>` の形ならラベル付き) と画像 1 枚 (Pillow が要る). 表にはヘッダーから読んだ幅, 高さ, チャンネル数, 色の形式, 大きさ |
| `text_lines` | text | 1 行 1 文の `.txt`, `<クラス>/<文>.txt` のディレクトリ. 表には文, 文字数, 語の数 |
| `pointcloud` | pointcloud | `.ply` (ASCII とバイナリ), `.pcd` (ASCII), `.xyz` / `.pts`, `(点の数, 3 以上)` の `.npy`. 1 つのファイルか, `<クラス>/<点群>` のディレクトリ. 表には点の数, 各軸の範囲, 中心, 色と法線の有無 |
| `capture` | capture | 多視点の撮影 (`transforms.json` を持つディレクトリか, それを並べたディレクトリ). 下の「多視点の撮影」 |

表の中の列が日時で, 日時の順に並ぶ (か並べられる) 場合は `timeseries` と推定する. 表の中に長い文の列があり, 他に列が少ない場合は `text` の候補にもする.

### 多視点の撮影 (`capture`)

AR の端末などで物体の周りを撮った 1 回の撮影を 1 件とする. 1 件は「画像の並び, 各枚のカメラの姿勢, 深度と信頼度の画像, (あれば) 点群」のまとまりで, 1 つのファイルではない. 多視点の画像から 3D の形を作る学習の入力と, その撮影の質のばらつき (どの撮影なら使えるか) を確かめるために読む.

- 形: `transforms.json` (カメラの内部パラメータ `fl_x`, `fl_y`, `cx`, `cy`, `w`, `h` と, `frames` の各枚の `file_path` と `transform_matrix` (カメラから世界への 4 x 4)) を持つディレクトリ. 各枚の `raw_depth_file_path` (生の深度. 無ければ穴を埋めた `depth_file_path`. 16 bit の PNG. 単位は `depth.depth_format` (大文字と小文字は区別しない. millimeter, centimeter, meter. 分からなければミリ). `depth.invalid_value` (既定 0) は欠け) と `confidence_file_path` (8 bit の PNG, 0 から 255. 生の深度と組), `tracking_state`, 撮影全体の `coordinate_convention` (`world_up`, `camera_axes`, `depth` (深度の測り方. `z` か `ray`), `pixel_center` (画素の中心. 既定 0.5)), `capture.device_model`, `point_cloud.file_path` があれば使う. 無ければその列は欠損
- `transforms.json` に書かれた場所は, 撮影のディレクトリの中のファイルだけを使う (絶対パスや `..` で外を指す場所は無いものとする. 読み込みが手元の任意のファイルを読まないように). 中かは書かれた場所の文字の上で確かめ, 撮影の中のシンボリックリンクの先はたどる (データを共有するために置いたものとして, 撮影を置いた人の判断に任せる)
- 列: `path` (撮影のディレクトリ), `frames` (枚数), `tracked` (追跡できた枚数. `tracking_state` が無い枚は追跡できたとする), `width`, `height`, `fl_x`, `device`, `depth_source` (`raw` 生の深度, `smoothed` 穴を埋めた深度 (欠けがほぼ無いので有効率は高く出る), `mixed`), `depth_valid` (深度の欠けでない画素の割合. 枚ごとの平均), `depth_confident` (信頼度が `min_confidence` (既定 128) 以上の画素の割合. 形の違う信頼度の画像は数えない), `distance_min`, `distance_median`, `distance_max` (枚ごとの深度の中央値 (メートル) の最小, 中央値, 最大. 背景も含む), `view_gap` (物体の中心から見たカメラの方位の, 最も大きい隙間 (度)), `points` (点群の点の数), `missing_files` (無いか外を指す画像の数), `error` (読めない理由)
- 深度, 距離, 方位は, 追跡できた枚だけで求める (追跡できなかった枚の姿勢は正しくない)
- 方位の隙間: 物体の中心は各枚の視線の直線に最も近い点 (最小二乗. 直線への距離は向きの符号に依らない). 上の向きは `world_up`, 無ければ各カメラの右の軸に最も垂直な向き (傾けずに撮れば右の軸は水平なので, 見下ろして撮っても傾かない. 符号はカメラの上の軸の平均に合わせ, `camera_axes` に OpenCV か +Z forward とあればカメラの -Y が上). 上の向きに垂直な面に写した方位の, 隣どうしの差の最大. 物の周りを回った撮影でない場合 (視線がほぼ平行で中心が決まらない, 中心が半分以上のカメラの後ろ, カメラが中心から水平に撮影距離の 1 割 (深度が無ければ 5 cm) も離れていない) は欠損にし, 気付き (`no_orbit`) を出す
- 深度は Pillow で読む (無ければ深度の列は欠損にし, 気付きに書く). 画像の画素は読まない (大きさは `transforms.json` の `w`, `h`)
- `capture_layout(item, distance=None)` は, 1 回の撮影のカメラを物の中心から上から見た配置 (各枚の面の上の位置 (メートル), 追跡できたか, 最も大きい隙間とその始まりの方位) にする (画面で周回の欠けを描くため. 回った撮影でなければ位置は None. 表の `view_gap` と同じ判定にするには, `distance` に表の `distance_median` を渡す. 方位は上から見て反時計回り (y は上向きの座標. y が下向きの画面の座標では y を反転して描く))
- `load_item(i)` は, 内部パラメータ, 各枚 (画像, 生の深度, 穴を埋めた深度, 信頼度の場所 (撮影のディレクトリの中にある場合だけ. 無ければ None), 4 x 4 の姿勢, 追跡の状態), 点群の場所, 座標の決まりの辞書を返す
- 気付き: 読めない撮影 (`unreadable_items`), 追跡できなかった枚 (`tracking_lost`), 無いか外を指す画像 (`missing_files`), 深度の信頼度の低い撮影 (`low_depth_confidence`. 信頼できる画素が 3 割未満. 深度の 1 画素より細い物や遠い物は信頼度が落ちる), 周回の大きな欠け (`view_gap`. 90 度以上), 回った撮影と見なせない (`no_orbit`), 画像の大きさがそろわない (`mixed_sizes`), 撮影が上限 (1 万件) を超えた (`too_many_files`), Pillow が無い (`missing_reader`)
- 版 1 の前処理と書き出しは対象外 (`prepare` は誤り. 撮影は 1 行の列の正解に収まらない). 撮影と正解の点群の対は, 版 2 の約束で書き出す (`export_capture_clouds`. 下の「書き出しの版 2」)

## 6. 分析

`profile(data, target=None)` は JSON にできる辞書を返す.

- **概要**: 種類, 行数, 列数, メモリ, 重複した行, 見本を使ったか
- **列ごと**: 推定した型 (`numeric`, `categorical`, `boolean`, `datetime`, `text`, `id`, `constant`), 欠損の数と割合, 異なる値の数, 数値なら平均, 標準偏差, 分位点, 歪度, 外れ値 (四分位範囲の 1.5 倍の外) の数, ヒストグラム (値の幅が浮動小数の誤差ほどしかない列は, 全て同じ値の列と同じく範囲を ±0.5 に広げる). カテゴリなら頻度の上位. 文なら長さの分布. 日時なら範囲と間隔
- **列の間**: 数値の列の相関 (Pearson と Spearman), カテゴリの列の関連 (Cramér の V)
- **目的の列との関係** (`target` がある場合): 目的の列の分布 (分類ならクラスの割合), 各列と目的の列の関連の強さ (数値と数値は相関, 数値とカテゴリは相関比, カテゴリとカテゴリは Cramér の V) の順位
- **時系列** (`timeseries`): 時刻の間隔 (最も多い間隔, 抜けと重なり), 範囲, 列ごとの自己相関 (周期の候補), 移動平均と傾向
- **種類ごと**: 画像は大きさとチャンネルの分布, 壊れたファイル. 文は長さ, 語彙, 頻出語. 点群は点の数, 範囲, 属性. 多視点の撮影は枚数, 深度の有効率と信頼できる割合, 撮影距離 (上の「多視点の撮影」)
- **気付き**: 下の表

| 気付き (`code`) | 内容 |
| --- | --- |
| `high_missing` | 欠損が多い列 (30 % 以上) |
| `constant` | 値が 1 つしか無い列 |
| `near_constant` | 最も多い値が 95 % 以上の列 |
| `id_like` | 全て異なる値で, ID らしい列 (学習に使うと覚えるだけになる) |
| `duplicate_rows` | 全く同じ行 |
| `high_cardinality` | 異なる値がとても多いカテゴリの列 |
| `skewed` | 歪度が大きい数値の列 (対数を取るなどの候補) |
| `outliers` | 外れ値の多い数値の列 |
| `high_correlation` | とても強く相関する数値の列の組 (どちらかで足りる) |
| `target_leak` | 目的の列とほぼ同じ情報を持つ列 (リークの疑い) |
| `class_imbalance` | 分類の目的の列のクラスの偏り |
| `target_missing` | 目的の列の欠損 |
| `irregular_interval` | 時系列の時刻の間隔の抜けや重なり |
| `mixed_sizes` | 大きさやチャンネル数がそろわない画像 |
| `unreadable_items` | 読めない画像や点群のファイル, 読めない撮影 |
| `invalid_points` | 座標が数でない点 (NaN, inf) を含む点群 |
| `duplicate_items` | 同じ文か, 中身が同じ画像 (分割をまたぐと検証が甘くなる) |
| `empty_items` | 空の文 |
| `group_overlap` | グループの列 (`split.column`) の同じ値が複数の分割にまたがる (`prepare` が分割の後に出す. 「前処理のレシピ」) |
| `item_overlap` | 同じ画像が複数の分割にまたがる (`prepare` が分割の後に出す) |
| `panel_series` | 時系列で, 店ごとのように複数の系列が同じ時刻に並ぶ (lag の `by` で系列ごとにずらす) |
| `mixed_forms` | 表記 (全角と半角, 大文字と小文字, 前後の空白) だけが違うカテゴリの値 (目的の列でも出す) |
| `tracking_lost` | 多視点の撮影に, 追跡できなかった枚がある |
| `missing_files` | 多視点の撮影の `transforms.json` にある画像が無いか, 撮影のディレクトリの外を指す |
| `low_depth_confidence` | 多視点の撮影で, 信頼できる深度の画素が 3 割未満 |
| `view_gap` | 多視点の撮影で, 物の周りを回った方位に 90 度以上の隙間がある |
| `no_orbit` | 多視点の撮影が, 物の周りを回った撮影と見なせない (方位の隙間を求めない) |
| `too_many_files` | ファイル (や撮影) が上限を超え, 先頭だけを読んだ |
| `missing_reader` | 読むのに要るライブラリ (Pillow など) が無く, 一部の列を求めていない |
| `multiple_sheets` | Excel に他のシートがある (読み込みの `sheet` で選ぶ. 無い番号や名前は誤り. `source` と概要の `sheets` に全ての名前, `sheet` に読んだシート) |

画像, 文, 点群では読み込みの表の列 (場所, 幅, 点の範囲など) を学習に使わない (中身を配列にする) ので, 列の気付きは目的の列についてのもの (`class_imbalance`, `target_missing`, 目的の列の `mixed_forms`) だけを出す.

表の読み込み (csv, json, parquet, excel) は `text_column` で文の列を指定すると, 文のデータ (1 行が 1 つの文. 他の列も残し, `length` と `words` を足す (名前が重なれば番号を付け, 役割 `length`, `words` に記録). 欠損の文は空の文) として読む. 文の列は中身として読むので, 表の手順で書き換えると誤りにし (行を絞る手順は使える), 表記のゆれは中身の手順の `normalize_text` でそろえる. 書き出したデータセットの `text_column` に文の列の名前を残す (新しい表からこの列を取り出して `transform_item` に渡す). 日時の列があっても時系列にはしない. `kind: table` で, 日時の列があっても表として読む.

文のデータの分析 (`items.tokenizers`) では, 文を区切る単位の候補 (文字, 語, 部分語) を同じ物差しで比べ, `vocabulary` の引数を勧める. 文の区切り方は言語や書き方で向き不向きが大きく (英語を文字で区切ると並びが長くなり, 語で区切ると語彙に無い語が増える. 日本語は語で区切っても漢字とかなは 1 文字ずつ), 測って決める.

- 見本 (最大 5000 件の空でない文) を無作為に 8 対 2 に分け, 8 割で語彙を作り, 2 割で測る (2 割が 10 件に満たない場合は, 語彙を作った文で測り, その旨を `notes` に書く). 部分語は語彙の大きさの上限を 500, 2000, 8000 の 3 つで作る (文字の種類より十分に大きいものだけ. 文が少なく同じ語彙になれば 1 つに)
- 測るもの: 語彙の大きさ, 1 つの文のトークンの数 (平均と 95 % 点), 語彙に無いトークンの割合 (2 割の文で), 勧める長さで切られる文の割合
- 勧め方: 語彙に無いトークンが 1 % 以下の候補を語彙の小さい順にたどり, 95 % 点が今の候補より 2 割以上短くなる場合だけ大きい語彙に移る (語彙が大きいほど埋め込みが大きく, 少ないデータでは学びにくいため). 全ての候補が 1 % を超える場合は, 最も少ないもの. 勧めた理由 (`reason`) は画面に出す. 長さは 95 % 点を 8 の倍数に切り上げる (512 まで)
- `tokenizers` が入っていない場合は部分語の候補を除き, その旨を `notes` に書く

気付きは `{severity, code, message, columns}` の辞書. `message` は日本語で, 理由と次にできること (前処理の手順の候補) を書く.

## 7. 前処理のレシピ

前処理は手順の並び (レシピ) で書く. 手順は登録簿に集め, 種類ごとに使えるものが違う.

手順に書けるのは, `op`, 当てはめた値 (`state`) と, その手順の登録簿にある引数 (`register_step` の `params` に書いた鍵) だけ. 知らない引数があれば `load_recipe` で読んだ時点で, 手順と引数の名前を挙げて止める (新しい版の ML-EDA で書いたレシピを古い版で読むと, 知らない引数を無視して別の列を作り, 後の手順で分かりにくい誤りになるため). 中身の手順 (`item_steps`) も同じく, `op`, `state` と, 中身の手順の登録簿の引数 (`ItemStep.params`) だけを書け, 知らない引数は `load_recipe` で, 中身の手順の位置と名前, 引数の名前を挙げて止める (黙って無視すると, 別の配列を作るため). `item_steps` が並びでなければ誤り. 知らない手順と種類に合わない手順は, 種類の分かる `prepare` (と `preview_items`) で止める.

```yaml
format_version: 1
target: species           # 目的の列
task: classification      # classification, regression, forecasting など
steps:
  - {op: drop_columns, columns: [id]}
  - {op: impute, columns: [age], strategy: median}
  - {op: one_hot, columns: [sex]}
  - {op: standardize, columns: auto}
split:
  method: stratified      # random, stratified (分類), time (時系列は時刻の順), group,
                          # group_time (グループと時刻の組), stratified_group (グループの層化)
  column: customer_id     # グループの列 (書かなくてよい. 下の「グループの列」)
  valid: 0.2
  test: 0.1
  seed: 0
  unlabeled: drop         # 目的の列の欠けた行. keep で unlabeled の分割に残す (下の「正解の欠けた行」)
```

- **グループの列**: `split.column` に顧客や患者の ID のような, 同じ人や物の行をまとめる列を書く. `group`, `group_time`, `stratified_group` の分割では同じ値の行を同じ分割にまとめ (新しい人に当てはめる力を測る), 他の分割のしかたでは同じ値が複数の分割にまたがるかを確かめて, `prepare` の気付き (`group_overlap`) にする (時刻の順の分割では, 同じ人が過去と未来にまたがるのは普通なので `info`, 他は `warning`. 気付きの文は, 時刻の順なら `group_time`, 層化なら `stratified_group`, 他は `group` を勧める). 分割の前の手順でこの列を落としても, 分割には落とす前の値を使う (学習に使わない ID の列で分けるため. 列が残っていれば手順をかけた後の値). 確かめには元の行の値を使い, 欠損は数えない (分割では欠損の行を 1 つのグループにまとめる). 書いた列が無ければ, 分割のしかたに依らず誤り. 問題の設定 (ML-Quest) に同じ相手の行をまとめる列があれば, ML-Quest が作るレシピの雛形がこの欄に書く
- **正解の欠けた行**: 目的の列の欠けた行は, 既定 (`split.unlabeled: drop`) では手順の前に落とす. `keep` にすると, 落とさずに `unlabeled` という名前の分割に残す (半教師あり学習や異常の検知のように, 正解の付いた行が少なく, 正解の無い行も学習に使いたい場合のため). 目的の列 (`target`) を書いていないレシピで `keep` は誤り (`load_recipe` で読んだ時点で止める. 読めても前と後の様子と書き出しの全てで止まるレシピを残さないため. データの役割だけで目的の列を決めている場合も, `keep` ではレシピに `target` を書く)
    - 正解の付いた行の前処理と分割と当てはめは, `drop` と全く同じ (`unlabeled` の行は値を学ぶ手順にも, 分割の割合と層化にも, 分割の前の手順にも入れない). 書き出す train, valid, test は `drop` の場合と同じ中身になる
    - `unlabeled` の行には, 推論のとき (`Dataset.transform`) と同じかけ方で, 学習用で当てはめた値をそのままかける (当てはめ直さない. 行を絞る手順は目的の列を見ず, 過去の値の列は推論と同じ前後関係). 推論と同じく, 重複の手順は落とさない. 行を絞る手順で落ちた行は除く. 学習に使う列はその値, 他の列 (ID など) は元の値, 目的の列は欠損. 正解の無い行の情報を前処理に入れる (正解の無い行も含めて標準化するなど) ことは今はしない (検証用とテスト用の当てはめと同じ値にそろい, 推論のときとも同じになるため)
    - 画像, 文, 点群は, `unlabeled` の件にも学習用で当てはめた中身の手順をかけ, 配列 (`unlabeled_items.npy`) にする (表の列は学習に使わないので元の値)
    - 学習に使う列の欠損が `unlabeled` の分割にだけ残る場合は注意 (`notes`) にする
    - 分割をまたぐ重なりの気付き (`group_overlap`, `item_overlap`) は正解の付いた分割だけで確かめる (同じ人の正解の無い行を学習に使うのは普通なため)
- **時刻の順の分割**: 時刻で並べた後ろの部分を検証用とテスト用にする. 件数で切った境目の時刻の行は後ろの分割にそろえ, 同じ時刻の行 (店ごとの売上の同じ日など) が学習用と検証用にまたがらないようにする
- **グループと時刻の組の分割** (`group_time`): 相手ごとの時系列で, 同じ相手を 1 つの分割にまとめつつ, 後から現れた相手を検証用とテスト用にする (新しく現れる相手に当てはめる力を, 未来の向きで測る). グループの列 (`split.column`) と日時の列が要り, どちらかが無ければ誤り. グループを最初の時刻の順に並べ (最初の時刻が同じグループは値の文字の順で, 境目では別の分割に分かれうる. 時刻の順の分割と違い, 同じ時刻をそろえるとグループの数で大きく外れるため), 行を並べた位置で件数を切り, 境目をまたぐグループは後ろの分割にそろえる (時刻の順の分割の境目の時刻と同じ. 大きなグループが境目にあると, 検証用やテスト用が割合より多くなる). 時刻の読めないグループは先頭 (学習用) に置く. 守るのは「後ろの分割の相手は, 前の分割の相手より後に現れた」ことで, グループの中の行の時刻は分割をまたいで重なりうる (長く続く相手の後半の行は, 後から現れた相手の行より後の時刻のことがある). 並べ方を最後の時刻でなく最初の時刻にするのは, 新しく現れた相手を当てる使い方 (現れた時点で予測する) に合わせるため
- **グループの層化** (`stratified_group`): 同じ相手を 1 つの分割にまとめつつ, 目的の値の割合を分割の間で近くする (少ないクラスの相手が検証用に入らないことを防ぐ). グループの列と目的の列が要る. 各グループの層は, そのグループの行で最も多い目的の値 (同じ数なら文字の小さい値. 層化の分割と同じく値を文字にそろえる). 検証用とテスト用の行の数を層の行の数に比例して配り (層化の分割と同じ最大剰余法), 層ごとに無作為に並べたグループを, 入れると配った数に近づく限りテスト用, 検証用の順に入れる (層ごとの数はグループより小さくなりやすいので, `group` と違い少し超えてもよい). 層で配り残した数と超えた数は次の層に回す (クラスが多く, 層ごとの数がグループの半分より小さい場合も, 全体で割合に近づく). 全ての層の後に全体の数に届かなければ, 学習用のグループを, 入れると全体の数に近づく順に足す (割合があるのに 0 件なら, 学習用にグループが 2 つ以上残る限り, 最も近いグループを 1 つ入れる. `split_counts` の 1 件以上の決まりと同じ). 値の混ざったグループが多いと割合は近似になる. 回帰と時系列の予測のタスクでは誤り (`load_recipe` で止める. 目的の値で層を作れないため, `group` を使う). タスクを書かない場合も, 目的の値が 20 種類より多く行の半分より多い (ほぼ全て違う) と誤り
- **グループでまとめた分割の件数の注意**: `group`, `group_time`, `stratified_group` では, 割合を書いた分割が 0 件になった場合と, 行の数が割合の数 (`split_counts`) から半分より多く外れた場合に, `prepare` の `notes` に書く (書き出すと `dataset.yaml` の `notes` に残る)
- 新しい分け方はレシピの版 1 に含む (`split.method` の値を足しただけで, この値を知らない ML-EDA は「知らない分割のしかた」で止まり, 黙って別の分け方をしないため)
- **当てはめと適用を分ける**: 平均や語彙のように, データから値を学ぶ手順 (標準化, 欠損の補完, 符号化) は, 分割した後の学習用のデータだけで当てはめ (`fit`), 同じ値を検証用とテスト用に適用する. 検証用のデータの情報が学習に漏れないように
- **分割の前にかける手順**: 値を学ぶ最初の手順より前にある手順 (列や行を落とす, 重複を落とす, 過去の値の列など) は, 分割の前に全体にかける. 分割をまたぐ重複を落とせ, 時系列の過去の値も分割の境目で切れない
- **列の決め方**: `columns: auto` は, 役割のある列 (目的の列, 日時の列, ID の列) を除いた, 手順に合う型の列. 決めた列は手順の `state.columns` に保存し, 推論のとき (`Dataset.transform`) も同じ列を使う. 推論のときは, 行を落とす手順 (重複, 欠損, 条件) も過去の値の列の前後関係を学習のときとそろえるためにかけ, 最後に入力の行の並びに戻す (重複した行は残した行と同じ値, 落とした行は欠損にし, 落とした手順を `attrs["dropped"]` で返す. 欠損の手順は目的の列を見ず, 目的の列で絞る手順は目的の列が分からない行を残す. 目的の列が分からない先の行を予測するため). 過去の値の列が目的の列を読む場合, 学習のときは目的の列が分かる行だけで前後関係を作ったので, 分かる行は分かる行だけでかけ, 分からない行は全ての行でかけた値を使う. 同じ名前の列がある表は誤りにする. 目的の列を書き換える手順は目的の列だけを除いてかける (入力と行がそろい, 同じ手順で変えた特徴量は学習のときと同じ値になるように. 除いた目的の列の欠損の印の列は 0). ただし目的の列の過去の値の列 (lag) があり, 目的の列 (過去の値) を渡した場合は, 目的の列にも学習のときと同じ手順をかける (lag が学習のときと同じ値を読むように). 過去の値の列 (lag) は目的の列を読むだけなのでかける (目的の列の過去の値を含めて渡す. 無ければ目的の列を除いてかけ, 後の手順で足りない列を誤りにする). 当てはめた列が入力に無い場合は, 手順の途中で落ちる前に列の名前を挙げて誤りにする (列を落とす手順 `drop_columns` の列は入力に無くてよい)
- カテゴリの値は, 型に依らない文字にそろえる (整数の列に欠損が入って 1 が 1.0 になっても同じカテゴリ). 欠損はカテゴリにしない
- 当てはめた値はレシピと一緒に保存し, 後から新しいデータ (推論のとき) に同じ前処理をかけられるようにする
- 手順ごとの前と後を `preview(data, recipe, upto)` で返す (GUI で 1 段ずつ確かめるため)
- 表の手順: 列を落とす, 行を絞る (`compare` で比べ方を書く), 型を変える, 欠損の補完 (平均, 中央値, 最頻値, 定数), 欠損の行を落とす, 外れ値の切り詰め, 対数, 標準化, 最小と最大の正規化, ワンホット, ラベルの番号付け, 日時の分解 (年, 月, 曜日, 時), 表記のゆれをそろえる (`normalize_text`. NFKC と前後の空白), 時系列のずらし (lag) と移動平均 (`by` で系列ごと) (lag の `columns: auto` は目的の列も選ぶ. 予測では目的の列の過去の値が最も大事な手がかりで, ずらすので未来の値は使わない). lag は既定では行でずらす. `time` (時刻の列) と `freq` (1 つ分の間隔. `1D`, `1h` など) を書くと時刻でずらす: k つ前は k × freq だけ前の時刻の同じ系列の値 (`match: previous` (既定) はその時刻が無ければそれより前で最も近い値, `exact` は無ければ欠損), 幅 w の移動平均は w × freq 前からその時刻の前までにある値の平均 (行でずらす場合と違い, 値が 1 つでもあれば欠損にしない). 移動平均は既定で 1 つ前から始まる. `gap` (1 以上の整数. 既定 1) を g にすると, g つ前から始まる幅 w の平均にする (時刻でずらす場合は [時刻 - (g - 1 + w) × freq, 時刻 - (g - 1) × freq) にある値の平均で, 休みの日などでその時刻に行が無くても, 窓に値があれば平均を出す. 列の名前は `<列>_mean<幅>_gap<g>`. 決める時点で 1 つ前の値がまだ分からない予測のため. 問題の設定の「決める時点で何期前まで分かるか」に合わせる). 系列と時刻が重なる行は, ずらした値には後の行を使い, 移動平均には全てを入れる. 時刻の読めない行は欠損. ずらす列は数値だけ. freq は長さの決まった間隔だけ (月や年は不可). 休みの日のような抜けを挟んでも, 7 つ前が暦の 7 日前 (休みなら 8 日前) になる
- 画像, 文, 点群は, 表 (1 行 1 件の様子) の手順で件を絞ってから, 中身の手順 (`item_steps`) で 1 件ずつ配列にする. 中身の手順も学習用の件だけで当てはめる (画像の正規化は学習用から無作為に選んだ最大 500 件, 語彙は学習用の全ての文). 配列は 1 件ずつファイルに書き (全てをメモリに並べない), 読むときはファイルから少しずつ読む. 全ての件の形がそろわない場合は理由付きの誤り
- `prepare(data, recipe, read_items=False)` は中身を読まずに, 中身の手順の確認 (知らない手順, 種類に合わない手順, 省けない引数, 文の vocabulary) と, 読み込みの表から分かる書き出しで失敗しそうなこと (読めない件, 大きさ, 色の形式, 点の数のばらつき) を注意 (`notes`) にする. 画面の前と後の様子に使う
- **分割の後に分かる気付き**: `prepare` は分割をまたぐ重なりを, 分析の気付きと同じ形 (`{severity, code, message, columns}`) で `Prepared.findings` に返し, その文を `notes` にも足す (画面は今の注意の欄にそのまま出せ, 書き出すと `dataset.yaml` の `notes` に残る. 約束の版は変えない). 確かめるのは元の行の値 (分割の前の手順で変える前). 中身を読まない `read_items=False` でも出す
    - `group_overlap`: グループの列 (上) の同じ値が複数の分割にまたがる (またがる値の数と行の数, 例)
    - `item_overlap`: 同じ画像 (`digest` が同じ) が複数の分割にまたがる. 分割の前に `drop_duplicates` (`columns: [digest]`) で落とすよう案内する
- `preview_items(data, recipe, count, fit_limit)` は, 中身の手順を学習用の少ない見本 (既定 100 件) で当てはめ, 学習用から無作為に選んだ数件にかけた前と後を返す. 画面で手順の効き方 (大きさ, 正規化, 語の番号, 点の数) を見るため
    - 画像: `resize` (大きさをそろえる), `grayscale` (灰色), `rgb` (灰色とカラーが混ざる場合に 3 チャンネルに), `normalize` (学習用の平均と標準偏差で正規化し, (チャンネル, 高さ, 幅) に)
    - 文: `vocabulary` (学習用の文で語彙を作り, 語か文字の番号の決まった長さの並びにする. 0 は埋め草, 1 は語彙に無い語. `unit` は `char` (文字), `word` (語. 文字と数字の並び, 漢字とかなは 1 文字ずつ), `subword` (学習用の文で BPE の部分語の語彙を作る. 空白と記号で区切ってから, 1 つの部分語は 16 文字まで. `tokenizers` が要る))
    - 点群: `sample_points` (点の数をそろえる), `normalize_cloud` (中心を原点にし, 最も遠い点までを 1 にする)
    - 領域: `resize_mask` (領域の大きさを最も近い画素でそろえる. 値を混ぜない). 版 2 の書き出しが画像の `resize` から決める手順で, 版 1 のレシピには書けない (領域の種類のデータが無いため)

## 8. 書き出し (学習との約束)

`export_dataset(data, recipe, path)` は次のディレクトリを作る.

```
<データセット>/
├── dataset.yaml        # 説明 (版, 種類, 目的の列, タスク, 列と型, 分割の件数, 元のデータ, レシピ)
├── recipe.yaml         # 当てはめた値を含むレシピ (新しいデータに同じ前処理をかけるため)
├── train.parquet       # 分割ごとのデータ (表と時系列. parquet が無い場合は csv)
├── valid.parquet
├── test.parquet
├── unlabeled.parquet   # 目的の列の欠けた行 (split.unlabeled: keep の場合だけ)
└── train_items.npy     # 画像, 文, 点群の中身の手順をかけた配列 (分割ごと. 表には無い)
```

`dataset.yaml` (版 1) の項目.

| 項目 | 中身 |
| --- | --- |
| `format_version` | 版 (1) |
| `name`, `created_at` | 名前と作った時刻 |
| `kind`, `task`, `target` | 種類, タスク, 目的の列 |
| `features` | 学習に使う列の名前と型 (目的の列は含まない) |
| `classes` | 分類のクラス (番号の順) |
| `splits` | 分割ごとのファイルと件数 (画像などは中身の配列のファイル `items` と形 `shape` も). 分割の名前は `train`, `valid`, `test` と, `split.unlabeled: keep` の場合の `unlabeled`. 件の無い分割は書かない |
| `source` | 元のデータの場所, 読み込み, 大きさと更新時刻 |
| `recipe` | 前処理のレシピ (`recipe.yaml`) |
| `notes` | 前処理の後の注意 (数値でない列が残っているなど) |

**モデルの入力** (`model_inputs(path)`): 書き出したデータセット (版 1 と, ファイルの組の版 2 と 3) の説明から, モデルが受け取る入力と出す値の数を JSON にできる辞書で返す. 画面 (ML-Fathom) がデータセットの一覧で「モデルに要るもの」を見せ, モデルの定義 (ML-ModelControl の `inputs` と最後の層の出す数) をデータに合わせるため. 分割のデータは読まない (画像などの中身の配列は, 型を知るためにファイルの頭だけを読む).

| 鍵 | 中身 |
| --- | --- |
| `inputs` | 入力の並び. 1 つは `{name, shape, dtype}`. 版 1 の入力は `tensors` の特徴量 1 つだけで, 名前は `x`. 形はバッチの次元を `null` にした形 (表と時系列は `[null, 学習に使う列の数]` で `float32`. 画像, 文, 点群は中身の配列の形と型. 例: 画像は `[null, 3, 64, 64]` の `float32`, 文の語の番号は `[null, 128]` の `int64`). 文の語の番号の入力は, 書き出したレシピの最後の `vocabulary` の手順の語彙の大きさ (`<pad>` と `<unk>` を含む語彙の数. 語の番号の上限 + 1) を `vocabulary` に持つ (モデルの埋め込み (`nn.Embedding` の `num_embeddings`) にそのまま使えるように. 文のデータセットだけはレシピも読む) |
| `task` | タスク (`classification`, `regression`, `forecasting`). 決めていない (`none`) 場合は `null` |
| `target` | 目的の列 (無ければ `null`) |
| `classes` | 分類のクラス (番号の順. クラスが無ければ空の並び). 分類でなければ `null` |
| `target_kind` | 正解の種類 (版 2 と 3 の `target.kind`. `mask`, `point_cloud`). 版 1 は `null` |
| `outputs` | モデルが 1 件に出す値の数. 分類はクラスの数, 回帰は 1, 時系列の予測は 1 (版 1 の説明は何期先までを持たず, 1 行に目的の値 1 つのため). タスクが無いか, 分類のクラスが無い場合は `null` |

ファイルの組 (版 2 と 3) は, 説明の `entries` の最初の入力と最初の正解の項目の種類の組から返す. `task` は `null`, `target` は正解の項目の名前, 入力の名前は入力の項目の名前. 値はどれも, ML-Quest の骨組み (ファイルの組の `train.py`) がモデルに渡す形と学ぶ数に合わせる (モデルの定義をそのまま骨組みで学習できるように).

| 組 | 入力 | `classes` と `outputs` |
| --- | --- | --- |
| 画像 (`image`) と領域 (`mask`) | `[null, チャンネル, 高さ, 幅]` の `float32` (骨組みが 0 から 1 にして (チャンネル, 高さ, 幅) に並べ替えるため). 大きさとチャンネルは項目の `shape` (書き出しが中身の手順の後の形を書く). `shape` の次元が `null` なら手順の `resize` (高さと幅) と `grayscale` (1) か `rgb` (3) から. どちらでも決まらない次元 (大きさの混ざる画像を手順なしで書き出したものなど) は `null` | `classes` は領域のクラスの名前 (値の小さい順), `outputs` はその数. 骨組みと同じ数え方で, 名前 (`classes`) があれば名前の付いた値, 無ければ値の一覧 (`values`) の全て (名前は値の文字). 名前の無い値 0 は背景 (`background`) のクラスとして足す (骨組みが背景も 1 つのクラスとして学ぶため) |
| 撮影 (`capture`) か点群 (`point_cloud`) と点群 (`point_cloud`) | `[null, 入力の点の数, 3]` の `float32`. 撮影は骨組みが深度から点に戻して選ぶので, 骨組みの config の既定 `data.input_points` と同じ 512 (`pipeline.ITEM_INPUT_POINTS`). 点群の入力は項目の `shape` の点の数がそろっていればその数, そろわなければ 512 | `classes` は `null`. `outputs` は出す点の数で, 正解の点群の項目の `shape` の点の数がそろっていればその数 (中身の手順の `sample_points` の後など), そろわなければ骨組みの config の既定 `data.target_points` と同じ 1024 (`pipeline.ITEM_TARGET_POINTS`) |

他の組 (画像と `boxes` など) は「まだ返せない」と誤りで止まる (項目の形は `dataset.yaml` の `entries` を見る). 知らない版も止まる.

`load_dataset(path)` は分割ごとの `DataFrame` を返す. `unlabeled` の分割の `arrays` と `tensors` は目的の値を返さない (`arrays` は y が None, `tensors` は特徴量だけ). 画像, 文, 点群では `arrays` と `tensors` が中身の配列を返し, `transform_item` で新しい 1 件に同じ中身の手順をかける. `arrays` で numpy の配列, `tensors` で PyTorch のテンソルにもできる (PyTorch が入っている場合). `transform` は新しいデータに当てはめた前処理をかける.

書き出しは, 前処理を済ませてから隣の一時ディレクトリに書き, 最後に入れ替える. 既にある場所を置き換えられるのは, 前に書き出したデータセット (`dataset.yaml` を持つもの) だけ.

版の決まりは ML-ModelControl と同じ. 項目を足す, 消す, 変える場合は版を上げ, 読む側は知っている版より新しいものを「この版は読めない」とする.

`splits` の分割の名前は版 1 の初めから決まった組ではない (検証用とテスト用の割合が 0 なら書かない) ので, 読む側は名前を指して分割を選ぶ. `unlabeled` の分割は版 1 に含む (`train`, `valid`, `test` の目的の列に欠損は無く, 正解の無い行は名前の違う分割にだけ入る. ML-Quest が作る ML-Found の学習のスクリプトの雛形, ML-Inference の一式の作成, ML-Fathom の画面は, `train`, `valid`, `test` を名前で選ぶか, 全ての分割の件数を並べて見せるだけで, 知らない名前の分割を正解のある分割として使わない). 読む側が全ての分割を正解のある分割として回す場合は, `unlabeled` を除く. レシピの `split.unlabeled` も同じ理由で版 1 に含む (この項目を知らない ML-EDA は読まず, 既定の `drop` として動く).

## 9. 書き出しの版 2 (ファイルの組とまとまり)

版 1 の約束は「1 件 = 1 行, 正解は列 1 つ」なので, 入力と正解がファイルの組 (画像と領域, 撮影と点群) のデータや, 1 件がファイルのまとまり (多視点の撮影) のデータを書けない. これらは版 2 の約束で書く. 版 1 で書けるものは版 1 のまま, 正解を作った処理を記録する, `task` は列の正解だけ, 書き出せる例は画像と領域の対と撮影と点群の対.

- **版 1 で書けるものは版 1 のまま**: 表, 時系列と, 画像, 文, 点群の列の正解 (クラスか値) は, `export_dataset` が版 1 で書く. 版 2 を書くのは, 正解がファイルのものとまとまりのもの (今は `export_image_masks` と `export_capture_clouds`) だけ. 版 1 しか知らない今の読む側を壊さないため
- **読む側の止まり方**: `load_dataset` (版 1 の読み込み) は版 2 を見ると「ファイルの組のデータセットなので `load_items` で読む」と言って止まる. `load_items` は版 1 を見ると `load_dataset` へ案内して止まる. 知らない版 (3 以上) はどちらも「この版は読めない」と止まる
- `pipeline.DATASET_FORMAT_VERSION` は版 1 (`load_dataset` が読む版) のまま変えない. ML-Inference がデータセットの写しの版の確かめに使っていて, 2 に上げると版 2 を版 1 として通してしまうため. 版 2 の番号は `pipeline.ITEMS_FORMAT_VERSION` (`items` からも使う)
- **版 3**: 版 2 に, 項目ごとの中身の手順 (`entries.<名前>.steps`. 下の「中身の手順」) を足した版. 中身の手順を渡した書き出しだけが版 3 で書き, 渡さない書き出しは今までと同じ版 2 で書く (手順の無いデータセットを版 2 しか知らない読む側が読めるように). 版を上げるのは, この欄を知らない読む側が推論で新しい 1 件に手順をかけず, 大きさの違う入力を黙ってモデルに渡すため (データセットの中のファイルは手順をかけた後なので, 学習で読むだけなら違わないが, 推論の取り違えは気付けない). 版 3 の番号は `pipeline.ITEMS_STEPS_FORMAT_VERSION`, `load_items` が読む版の組は `pipeline.ITEMS_FORMAT_VERSIONS` ((2, 3)). `ITEMS_FORMAT_VERSION` は 2 のまま (版 2 の番号として読む側が使っているため). 他の欄の意味は版 2 と同じ

```
<データセット>/
├── dataset.yaml         # 説明 (版 2)
├── items.parquet        # 1 行が 1 件の表 (parquet が無い場合は csv)
└── items/
    ├── 000000/          # 1 件のファイル (番号は表の行の順)
    │   ├── image.png
    │   └── mask.png
    └── 000001/
```

### 版 2 の説明 (`dataset.yaml`)

| 項目 | 中身 |
| --- | --- |
| `format_version` | 版 (2. 中身の手順を渡した書き出しは 3) |
| `name`, `created_at` | 名前と作った時刻 |
| `role` | 受け持ち. `predict` (予測する), `generate` (作る), `rank` (並べる), `group` (まとめる), `effect` (効果を見積もる). 値は ML-Quest の受け持ちと同じ |
| `target` | 正解. `kind` (正解の種類. `mask`, `point_cloud`, `boxes` など), `entries` (正解の項目の名前の並び), `origin` (正解の出どころ. 下) |
| `entries` | 名前を付けた項目 (入力と正解) の辞書. 欄は下の表 |
| `items` | 1 行が 1 件の表のファイル (`items.parquet` か `items.csv`) |
| `split` | 分割のしかた (`method`, `valid`, `test`, `seed`. グループで分けた場合は `column: group`. 渡した場合は `unlabeled`) |
| `splits` | 分割ごとの件数 (`{train: {items: 8}, valid: {items: 2}}`. 件の無い分割は書かない. 正解の無い件を書いた場合は `unlabeled` も) |
| `normalization` | 入力と正解にかけた座標の正規化 (かけた場合だけ. 下の「撮影と点群の対」) |
| `source` | 元の場所 (入力と正解のディレクトリの名前だけ. 下の「元の場所」) |
| `notes` | 書き出しの注意 (組にならなかったファイル, 分割をまたぐグループなど) |

`task` は書かない. `task` は列の正解 (分類, 回帰, 予測, 正解なし) だけのもので, 版 2 の種類は `role` と `target.kind` で表す.

項目 (`entries.<名前>`) の欄.

| 欄 | 中身 |
| --- | --- |
| `kind` | 項目の種類. `image`, `mask`, `point_cloud`, `capture` (今の書き出し), `boxes`, `vector`, `row` (表の 1 行), `text`, `value`, `class`, `id` (下の確かめで使う) |
| `role` | `input` か `target` |
| `placement` | 置き方. `file` (1 件に 1 つのファイル. 表の同じ名前の列に場所), `directory` (1 件に 1 つのディレクトリ. 撮影), `column` (表の同じ名前の列に値) |
| `pattern` | 置き方の形 (`items/{index:06d}/image{suffix}` など. Python の書式で, `index` は表の行の位置を 6 桁の 0 埋め, `suffix` は元のファイルの小文字の拡張子. 人と画面が読むため. 場所は表の列が正) |
| `formats` | ファイルの形式 (`png`, `ply`, `transforms.json` など) |
| `shape` | 1 件の形 (件ごとにそろわないか分からない次元は null). 1 つの配列の項目 (`image`, `mask`, `point_cloud`) は `load_items` の返す配列の形 (画像はチャンネルの次元を含む). 複数の配列を持つ項目 (`capture`) は共通の次元だけ ((枚数, 高さ, 幅). 画像のチャンネルや深度は読み込みの節の形) |
| `dtype` | 読んだ配列の型 |
| `units` | 単位 (`pixel`, `meter` など. 無ければ null) |
| `convention` | 座標の決まり (画像は左上が原点で (行, 列). 撮影は姿勢がカメラから世界, カメラの軸, 世界の上の向き, 深度の測り方, 画素の中心. 下の「撮影と点群の対」) |
| `values`, `classes` | 正解の値と, 値の名前 (`mask`, `boxes` など. `classes` は `value` と `name` の並び) |
| `steps` | 書き出しでかけた中身の手順の並び (版 3 だけ. 手順をかけた項目だけが持つ. 下の「中身の手順」) |

表 (`items`) の列: `id` (元の名前. 画像のファイルの stem, 撮影のディレクトリの名前), `split`, `group` (グループを渡した場合), 項目ごとの列 (`file` と `directory` はデータセットのディレクトリからの相対の場所, `column` は値), 他 (正規化の `shift_x` など).

**正解の出どころ** (`target.origin`). 正解が外の処理の出力の場合も, 何で作ったかは問わずに「入力のファイル群」と「正解のファイル」の組として受け取り, 作った処理を書いておく.

- `type`: `process` (今ある処理の出力), `annotation` (人が付けた), `measurement` (測った), `synthetic` (作った正確な正解), `unknown` (渡されていない. 既定)
- `name`, `settings`: 正解を作った処理 (か道具) の名前と設定
- `process` の場合, 正解はその処理の出力なので, 測れるのは「その処理との一致」で, モデルはその処理を超えられない. 後の段階 (ML-Found の評価, ML-Inference の結論) はこの欄を読んでそう書く. `annotation` も付けた人との一致

**分割**: 版 1 と同じく 1 件ごと. `random` (既定), `group`, `none` (全て学習用. 説明の `valid` と `test` は 0). `groups` (件の `id` からグループ) を渡すと既定は `group` で, 同じグループの件を同じ分割にまとめる (撮影は現場や物で分ける). 他の分け方でグループが複数の分割にまたがると, `group_overlap` と同じ注意を `notes` に書く. `groups` に無い `id` は誤り. 割合を指定した分割が 0 件になった場合 (グループが割合に収まらないなど) も `notes` に書く. `stratified` と `time` は今は誤り (正解がファイルなので層が無い. 時刻は件の表に時刻の列を持ってから).

**正解の無い件** (`split.unlabeled`): 既定 (`drop`) では, 正解のファイルの無い入力 (領域の無い画像, 点群の無い撮影) を除き, 数と例を `notes` に書く. `keep` にすると, 除かずに `unlabeled` という名前の分割に書く (版 1 の `split.unlabeled: keep` に当たる. 半教師ありの学習や, 推論の確かめに使えるように). `drop` と `keep` の他は誤り.

- 正解の付いた件の分割と中身は `drop` と全く同じ (`unlabeled` の件は分割の割合にもグループの重なりの確かめにも入れない). 表では正解の付いた件の後ろに `id` の順で続け, 正解の付いた件の番号 (`items/000000` など) も `drop` と同じ
- 入力は正解の付いた件と同じに書く (画像は同じ確かめ (読めるか, EXIF の向き. 後から正解を付け足すときに画素がずれないように) と同じ中身の手順, 撮影は同じ正規化と手順. 平行移動の列も持つ). 正解の項目の列は空 (null). 入力の項目の `shape` と `formats` は `unlabeled` の件も含めて求め, 正解の項目の `shape`, `values` などは正解の付いた件だけで求める
- `groups` は `unlabeled` の件には無くてよい (分割に使わないため. 無ければ `group` は空)
- 入力の無い正解 (画像の無い領域, 撮影の無い点群) は, `keep` でも除いて `notes` に書く
- 版は変えない (版 2 のまま. 中身の手順を渡せば版 3). 版 1 と同じく, 分割の名前は決まった組ではないので, 読む側は名前を指して分割を選ぶ (ML-Quest の骨組みは `train`, `valid`, `test` を名前で選び, ML-Inference の推論は入力の項目だけを読む). 全ての分割を正解のある分割として回す読む側は, `unlabeled` を除く. この欄を知らない ML-EDA は `split.unlabeled` を読まず, 今までと同じく除く

**前処理**: 中身の手順を渡さなければ, ファイルをそのまま写す (撮影と点群は座標の正規化だけ). 渡すと, 項目ごとに手順をかけたファイルを書く (下の「中身の手順」).

### 中身の手順 (`item_steps`)

書き出し (`export_image_masks`, `export_capture_clouds`) の `item_steps` に, 項目の名前から手順の並び (版 1 の `item_steps` と同じ登録簿の手順と同じ書き方. `{op: resize, width: 64, height: 64}` など) の辞書を渡すと, 1 件ずつ手順をかけたファイルを書き, かけた手順を項目の `steps` に残す (版 3). 大きさをそろえるなどを学習のコードで毎回書かず, 推論でも同じ手順をかけられるようにするため.

- **ファイルに残せる手順だけ**: 手順はファイルにかけて書くので, かけた後もその項目のファイルの形 (8 bit の画像, 領域, 点群) に収まる手順だけを使える. 項目ごとに使えるものは下の表. 他の手順 (画像の `normalize` は値が小数の (チャンネル, 高さ, 幅) になり, 点群の `normalize_cloud` は実寸と正規化の平行移動を壊し, 推論で元の大きさに戻せない) は誤り. 値を学ぶ手順 (`fit` のあるもの) は今は使えないので, `steps` は当てはめた値 (`state`) を持たない
- **引数**: 手順の登録簿にある引数だけ. 知らない引数は手順と引数の名前を挙げて誤り (黙って無視して違うファイルを書かないため). 大きさと点の数は 1 以上の整数
- **書いた手順**: 手順は渡した順にかける. `steps` には `op` と引数だけを書く (`{op: resize, width: 64, height: 64}`)
- **読み込み**: データセットのファイルは手順をかけた後なので, `load_items` は手順をかけずに読む. 項目の `shape` と `dtype` は手順をかけた後のもの
- **推論**: 新しい 1 件に同じ手順をかけるには, 画像, 領域, 点群は `transform_entry(データセット, 項目の名前, 中身)`, 撮影は `normalize_capture(撮影, 写す先, steps=項目の steps)` を使う (下の「推論のときの読み方」). 読む側の知らない手順 (新しい ML-EDA で足した手順) は, 手順の名前を挙げて誤りで止まる

| 項目 | 使える手順 | かけ方 |
| --- | --- | --- |
| 画像 (`export_image_masks` の `image`) | `resize`, `grayscale`, `rgb` | `read_image` で読んだ配列にかけ, PNG で書く (拡張子は `.png`). 領域の手順は書き出しが決める. 画像の `resize` ごとに, 同じ大きさの `resize_mask` (最も近い画素. 領域の値を混ぜない) を領域の `steps` に書く (画像と領域の画素がずれないように). `item_steps` に `mask` を渡すと誤り |
| 撮影 (`export_capture_clouds` の `capture`) | `resize`, `grayscale`, `rgb` | 各枚の画像にかけ, PNG で書く (`file_path` を `.png` に直す). `resize` では, 生の深度, 穴を埋めた深度, 信頼度を最も近い画素で, 画像と同じ倍率に (深度の値を混ぜない. 深度の画像の大きさが画像と違う撮影も, 比を保つ), 内部パラメータ (`fl_x`, `fl_y`, `cx`, `cy`, `w`, `h`. 枚ごとにあれば枚ごとも) を同じ倍率に直す. `cx` と `cy` は画素の中心 (`pixel_center`) を保って写す (`pixel_center` が 0.5 なら倍率をかけるだけ). 1 つの撮影の画像の大きさがそろわなければ誤り |
| 正解の点群 (`export_capture_clouds` の `cloud`) | `sample_points` | 単位をそろえ, 正規化の平行移動をかけた後の点群にかける (色は残し, 法線は落とす) |

書き出しは版 1 と同じく, 隣の一時ディレクトリに書いてから入れ替える. 既にある場所を置き換えられるのは, 前に書き出したデータセット (版に依らず `dataset.yaml` を持つもの) だけ.

**元の場所** (`source`): 書き出したデータセットは人に渡すことがあるので, 手元のディレクトリの構成を残さない. 入力と正解のディレクトリは渡した場所の名前 (`.` と `..` を畳んだ最後の部分. シンボリックリンクはたどらない. `~` だけと根は空) だけを書き (`images`, `masks` や `captures`, `clouds`), `paths: name_only` と `note` (名前だけを残したこと) を添える. 絶対パスもデータセットからの相対の場所も書かない (相対の場所も `../../` から手元の構成が分かるため). 読む側は `source` を読まない.

**既知の問題 (版 1)**: 版 1 の `source.path` は読み込んだ場所を常に絶対パスで書く. 版 1 は公開した約束で, 読む側 (ML-Inference など) がこの欄を使うかが分からないので, 変えていない. 版 1 のデータセットを人に渡すときは, 手元のパスが入っていることに気を付ける.

### 画像と領域の対 (`export_image_masks`)

`export_image_masks(images, masks, path, split=None, groups=None, classes=None, origin=None, name=None, overwrite=False, mask_suffix="", item_steps=None)`. Pillow が要る.

- 画像のディレクトリと領域のディレクトリ (それぞれ 2 階層まで) のファイルを, 名前の stem で組にする. `mask_suffix` (`_mask` など) を渡すと, 領域の stem の終わりからその文字を除いて組にする (`a.png` と `a_mask.png`). 1 つのディレクトリに同じ stem が 2 つあれば誤り (どれを組にするか決まらない). 片方にしか無いものは除き, 数と例を `notes` に書く
- 領域は 1 チャンネルの整数の画像 (`L`, `P` (パレットの番号), `1`, `I;16`, `I`). カラーの領域 (`RGB` など) は誤り (色とクラスの対応を決めていないため). 画像と領域の大きさの違う組は誤り. JPEG の領域は値が崩れるので注意に書く. EXIF の向き (1 以外) の付いた画像は誤り (画像は読むときに向きを直すが, 領域は直さないので画素がずれる. 領域をどちらの向きで塗ったかは書き出しでは分からないので, 黙って回さず, 向きを直して保存した画像とそれに合わせた領域を渡してもらう)
- 中身の手順 (`item_steps` の `image`) をかけると, 画像と領域を PNG で書く (領域は 8 bit か 16 bit の灰色. 値はそのまま). 領域の値が 0 から 65535 に収まらなければ誤り
- 項目: `image` (`kind: image`, 入力, `shape` は (高さ, 幅, チャンネル). チャンネル数は `read_image` で読んだ配列のもの (灰色は 1, 透明のある色は 4, 他の色は 3)), `mask` (`kind: mask`, 正解, `shape` は (高さ, 幅), `values` は全ての領域に出る値 (256 種類まで), `classes` は値の名前 (渡した場合. 値から名前の辞書 (整数の文字の鍵も) か名前の並び))
- `role: predict`, `target.kind: mask`

### 撮影と点群の対 (`export_capture_clouds`)

`export_capture_clouds(captures, clouds, path, split=None, groups=None, origin=None, cloud_units="meter", name=None, overwrite=False, item_steps=None)`. 中身の手順は `item_steps` の `capture` と `cloud` (上の「中身の手順」).

- 多視点の撮影 (上の「多視点の撮影」の読み込みで読めるもの) と, 点群のディレクトリの直下の `<撮影のディレクトリの名前>.<拡張子>` (点群の読み込みと同じ形式) を組にする. 読めない撮影と, 片方にしか無いものは除き, `notes` に書く. 姿勢が 1 つも無い撮影, 画像のある枚が 1 つも無い撮影, 読めない正解の点群があると, 書き出し全体を誤りにする (正解の組を黙って減らさないため)
- **正規化**: 1 件ごとに, 撮影の姿勢と正解の点群に同じ平行移動をかけ, 撮った物の中心 (書き出しで残す枚 (画像のある枚) のうち, 追跡できた枚の視線に最も近い点. 方位の隙間と同じ求め方. 決まらなければカメラの位置の平均. 追跡できた枚が無ければ残す枚の全ての姿勢で) を原点にする. 書き出した撮影から中心を求め直すと原点になる. 回転と拡大縮小はかけない (実寸 (メートル) と上の向きを残す. 寸法を測るため). 中心は入力 (姿勢) だけから決め, 正解の点群からは決めない (推論のときに同じ正規化をかけられ, 正解の位置が入力に漏れないように). 足した量を表の `shift_x`, `shift_y`, `shift_z` に残し (正規化した座標 = 元の座標 + shift), `normalization` に方法, 単位, かけた項目, 列を書く. 推論のときは, 同じ正規化を `capture_shift(撮影)` (足す量を求める) と `normalize_capture(撮影, 写す先)` (写して姿勢と撮影の点群に足す) でかけ, 出力を元の座標に戻すには shift を引く
- 撮影は写し直す: 各枚の画像, 生の深度, 穴を埋めた深度, 信頼度を同じ相対の場所に写し, `transforms.json` の姿勢を正規化して書く (深度はカメラから見た値なので変わらない). 他の欄はそのまま写すので, 世界の座標を持つ他の欄 (物の範囲など) には平行移動がかからない. 撮影の外を指すか無いファイルの欄は除く. 画像の無い枚は除く. 撮影が持つ点群 (`point_cloud.file_path`) も同じ平行移動をかけて PLY で書く (無いか撮影の外を指すか読めなければ除いて `notes` に)
- 正解の点群は `cloud_units` (`meter`, `centimeter`, `millimeter`) からメートルにそろえ, 2 進の PLY (x, y, z は float32. 色と法線があれば残す) で書く. 撮影の姿勢の単位はメートルとする
- 項目: `capture` (`kind: capture`, 入力, `placement: directory`, `shape` は (枚数, 高さ, 幅), `convention` は撮影の座標の決まり (下)), `cloud` (`kind: point_cloud`, 正解, `shape` は (点の数, 3), 単位はメートル, 座標は撮影の正規化した世界)
- `role: predict`, `target.kind: point_cloud`

**撮影の座標の決まり** (`entries.capture.convention`). 深度から点に戻すのに要るものを全て書く.

| 欄 | 中身 |
| --- | --- |
| `pose` | `camera_to_world` (`transform_matrix` はカメラから世界への 4 x 4) |
| `camera_axes` | カメラの軸 (撮影の `coordinate_convention.camera_axes`. 無ければ `OpenGL (+X right, +Y up, -Z forward)`) |
| `world_up` | 世界の上の向き (撮影の `coordinate_convention.world_up`. 無ければ null) |
| `origin` | `normalization` (正規化した世界) |
| `depth` | 深度の測り方. `z` はカメラの前の向きの軸に沿った距離 (光線に沿った距離ではない). `ray` は光線に沿った距離 |
| `pixel_center` | 画素の中心の位置. `0.5` は, 行 r, 列 c の画素の中心を (c + 0.5, r + 0.5) とする (`cx`, `cy` と同じ画素の座標. 左上の画素の左上の角が (0, 0)) |

`depth` と `pixel_center` は撮影の `coordinate_convention` に書かれていればそれを写し, 無ければ (null も) `z` と `0.5` とし, 書かれていない撮影の数と例を `notes` に書く. `depth` が `z` と `ray` のどちらでもないか, `pixel_center` が数でない撮影は誤り (`read_capture` も. 黙って読み違えないため). 撮影ごとの違いは既定を足してから比べる. 合成の見本 (`synthetic.render_view`) は画素の中心 (+0.5) を通る光線を, カメラの前の軸に 1 進む向き (OpenGL なら z 成分が -1) で当て, 当たった倍数を深度にするので, 深度は `z` で画素の中心は `0.5`. 見本の `transforms.json` にもそう書く. 多視点の撮影の読み込みと `read_capture` は深度の値を変えずに返す (単位をメートルにそろえ, 欠けを 0 にするだけ). OpenGL の軸で深度 d の画素 (r, c) は, カメラの座標で ((c + 0.5 - cx) / fl_x * d, -(r + 0.5 - cy) / fl_y * d, -d) になり, 姿勢をかけると世界の座標になる.

`depth` と `pixel_center` は版 2 の `convention` の欄 (他の欄の意味は変えず, この欄を知らない読む側は読まない. 無い説明は `z` と `0.5` として読む).

**推論のときの読み方**: 新しい撮影は `normalize_capture(撮影, 写す先, steps=None)` で学習と同じ正規化をかけ, `read_capture(写す先)` で `load_items` の撮影と同じ形の辞書に読む. 書き出しで中身の手順をかけたデータセット (版 3) では, `steps` に撮影の項目の `steps` を渡して同じ手順もかける. 正解と同じ形の点群は `read_cloud(ファイル)` で読む (`points` ((点の数, 3) の float64. 単位は元のファイルのまま), `colors`, `normals`). どれも `ml_eda` から使える.

### 新しい 1 件への手順 (`transform_entry`)

`transform_entry(dataset, name, value)` は, データセット (`load_items` の `ItemDataset`, `dataset.yaml` の中身の辞書, データセットのディレクトリのどれか) の項目 `name` に残した手順を, 新しい 1 件にかけ, `load_items` がその項目に返すのと同じ形で返す (推論のときに, 書き出しと同じ手順をかけるため. 版 1 の `transform_item` に当たる).

- `value`: 画像と領域はファイルの場所か配列 (画像は `read_image`, 領域は `read_mask` と同じ読み方), 点群はファイルの場所, (点の数, 3) の配列か `points` を持つ辞書
- 返すもの: 画像は (高さ, 幅, チャンネル) の uint8, 領域は説明の `dtype` の (高さ, 幅), 点群は (点の数, 3) の float32. 手順の無い項目 (版 2 も) はそのまま同じ形で返す
- 撮影は誤りにして `normalize_capture` へ案内する (撮影は写してから手順をかけ, 正規化の平行移動も要るため)
- 点群は手順だけをかける (書き出しの単位の換算と正規化の平行移動はかけない. 正解の点群は推論の入力ではないので, 新しい正解と比べるときに使う)

### 読み込み (`load_items`)

`load_items(path)` は版 2 と 3 のデータセットを読み, `ItemDataset` を返す. `info` (説明), `items` (表), `entries` (項目), `split(name, read=True)` (分割の件の並び. `len` と番号で 1 件を返すので, PyTorch の `Dataset` にそのまま包める).

- 1 件は辞書 (`id`, `group`, `split` と, 項目の名前から中身). 項目の名前に `id`, `split`, `group` は使えない (書き出しと `load_items` で誤り)
- `read=True`: `image` は (高さ, 幅, チャンネル) の uint8, `mask` は (高さ, 幅) の整数 (説明の `dtype`), `point_cloud` は (点の数, 3) の float32, `capture` は `intrinsics`, `poses` ((枚数, 4, 4). 無い姿勢は NaN), `images` ((枚数, 高さ, 幅, チャンネル) の uint8), `depth` ((枚数, 高さ, 幅) の float32, メートル, 欠けは 0. 全ての枚に深度がある場合だけ, 無ければ None), `confidence` (同じく uint8 か None), `tracking`, `convention` (撮影の `coordinate_convention` に, 無ければ `depth: z` と `pixel_center: 0.5` を足したもの) の辞書. 画像の大きさがそろわない撮影は誤り
- 返す配列は全て書き込める (`writeable` が True. 種類によらず同じ). Pillow の画像から作った配列は書き込めないので写して返す (そのまま `torch.from_numpy` に渡すと PyTorch が警告を出すため)
- `read=False`: ファイルとディレクトリの場所 (絶対パスの文字)
- `unlabeled` の分割の件の正解の項目は, `read` に依らず None (表の場所が空). 他の分割の件か入力の項目の場所が空なら, 件と項目の名前を挙げて誤り (壊れた表を黙って読まない)
- 知らない `kind` の項目は場所を返す. 知らない `placement` は誤り (読み方が分からないので黙って読み違えない)
- 表の場所はデータセットのディレクトリの中だけ (絶対パスや `..` は誤り. 書かれた場所の文字の上で確かめ, 撮影の読み込みと同じくシンボリックリンクの先はたどる)

### 合成の見本 (`ml_eda.synthetic`)

道具の確かめ用 (テストで使う. ML_tester の例でも使う). ml_eda の他は numpy と標準ライブラリだけで書く (PNG も自前で書くので Pillow も描く道具も要らない).

- `write_image_masks(root, count, size, seed, sizes)`: 雑音の上に円か四角を 1 つ置いた画像と, その領域 (0 が背景, 1 が円, 2 が四角) を `images/` と `masks/` に書く. `sizes` に (高さ, 幅) の並びを渡すと, 件ごとに順に繰り返した大きさで書く (大きさの混ざった見本. 書き出しの `resize` の確かめに使う)
- `write_shape_captures(root, shapes, views, size, points, seed, count)`: 球と箱の正確な点群 (面の上の一様な点) を `clouds/<名前>.ply` に書き, 物の周りの決まった姿勢から光線を当てて (解析的な交わり) 画像, 深度 (ミリの 16 bit の PNG), 信頼度を求め, 多視点の撮影の形で `captures/<名前>/` に書く. `shapes` を省くと既定の球 2 つと箱 2 つ. `count` を渡すと, `seed` から球か箱を `count` 個ばらつかせて作る (名前は `shape_000` から. 種類, 中心 (原点から水平に 0.5 から 1.5 m, 高さ 0.05 から 0.3 m), 大きさ (球の半径 0.08 から 0.18 m, 箱の各辺 0.1 から 0.3 m), 色が乱数. 1 つの撮影には 1 つの形だけが写るので, 中心の位置は正規化の平行移動にだけ効く. `shapes` と同時には渡せない. `count` は 1 以上の整数). `transforms.json` の `coordinate_convention` に `depth: z` と `pixel_center: 0.5` を書く

### 他の型を版 2 で書く形

版 2 が 2 つの例だけに合う形になっていないかの見本として, 次の 2 つの書き方を示す. どちらも書き出しと読み込みは無く, 足すときの形の見本.

- **検出 (物の箱)**: 項目 `image` (`file`, 入力) と `boxes` (`kind: boxes`, 正解, `placement: file`, `items/{index:06d}/boxes.json` に `[{box: [x1, y1, x2, y2], class: 0}]` の並び, `formats: [json]`, `units: pixel`, `convention: {origin: top_left, axes: [x, y], box: xyxy, edges: pixel_corner}` (x が列で, 画像の `axes: [row, column]` と順が逆なので明示する), `classes`, `shape: [null, 4]` (箱の数は件ごとに違い, 物の無い画像は空の並び)). `role: predict`, `target.kind: boxes`. 今の欄だけで書ける. 今の読み込みは知らない `kind` の場所を返す
- **並べる (利用者 × 品)**: 1 件 = 見せた 1 回. 項目 `user` と `item` (`kind: id`, `placement: column`), `clicked` (`kind: value`, 正解, `column`. クリックの 0 か 1 を関連度と見なす), 要求をまとめる列 `query` (`kind: id`, `column`. 要求ごとに並べて測るため). `role: rank`, `target.kind: relevance`. 同じ要求の件が複数の分割に分かれると要求ごとの順位を測れないので, `query` か利用者をグループにし, 並べるで `random` の分割は誤りにする. 利用者と品の特徴は件の表に並べず別の表を引く置き方 `lookup` (`table: users.parquet`, `key: user`) が要る. 分割は時刻で全体を切る (利用者ごとに最後を残すと他の人の未来が入る) か利用者で `group`. 今の読む側は知らない置き方 (`placement`) で止まるので, 黙って読み違えない

## 10. 安全

- 読み込みは手元のファイルだけ. ネットワークは使わない
- `pickle` を使う形式 (`.pkl`, `allow_pickle` の `.npy`) は読まない (任意のコードを動かせるため)

## 11. 課題の型への広げ方

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる. 版 1 の約束は「1 件 = 1 行, 正解は列 1 つ」で, ファイルの組とまとまりは版 2 で書く (上の「書き出しの版 2」). 広げる順は, 約束 (ファイルの形の版) を変えずに出せるもの → 約束の版を上げるもの → 型ごとの通り道.

- 型を足すときは, その型の分割の落とし穴を気付きにする: 推薦は時刻で全体を切る (利用者ごとに最後を残すと他の人の未来が入る), 効果は処置の後に決まる列と重なり (傾向が 0 か 1 に近い人), 自己教師はコーパスとテスト用の重なり, 撮影は現場や物で分ける
