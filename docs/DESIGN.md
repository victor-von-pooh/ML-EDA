# 設計

ML-EDA の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) にある.

## 1. 役割と位置づけ

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「データの分析」の段階でライブラリを受け持つ. 画面は ML-Fathom.

機械学習に使うデータを読み込み, 探索的に分析し (EDA), 前処理をして, 学習 (ML-Found) にそのまま渡せる形に書き出す. 表, 時系列, 画像, 文, 点群, 音声のように形の違うデータを, 同じ考え方で扱う.

- GUI のアプリ (ML-Fathom) が必要とすること (読み込みの結果, 分析の結果, 気付き, 前処理の前と後) は, このライブラリが JSON にできる辞書で返す. 画面に固有のものは入れない
- 学習とモデルの組み立ては対象外. 書き出したデータセットは, ML-Found の学習スクリプトがこのライブラリで読み込んで使う
- **問題の設定との分け方**: 何を予測するか (目的の列), タスクの種類 (分類, 回帰など) は問題の設定の段階が決める. ただしデータの理解は目的が決まる前から始められるので, 読み込みと分析は目的無しで動く. 目的の列とタスクの種類は, 前処理と分割と書き出しのときに要るので, レシピに書き, 書き出すデータセットの説明に記録する. レシピは利用者が書くか, 問題の設定 (ML-Quest) の受け渡しから作る (ML-Fathom の「問題の設定から始める」. このライブラリは ML-Quest を読まない)
- 他の段階のライブラリのコードを前提にしない

## 2. 他のリポジトリとの約束

### 公開の名前

他のリポジトリが使ってよい名前は, `ml_eda` の `__all__` にあり `from ml_eda import ...` で読めるものだけ. 元のモジュール (`ml_eda.pipeline` など) の名前も残すが, 他のリポジトリは `ml_eda` から読む. 画面と推論が使う次の名前の形を約束にする.

- `frame_view(frame, rows)`: 表の行数, 列と型, 先頭の `rows` 行を JSON にできる辞書で返す. 鍵は次の 3 つ
    - `rows`: 表の全ての行数 (`int`)
    - `columns`: 列ごとの `{"name": str, "dtype": str}` の並び (`dtype` は pandas の型の名前. 例 `int64`, `float64`, `object`, `datetime64[ns]`)
    - `head`: 先頭の行の並び. 1 行は列の順の値の並び. 値は `int`, 有限の `float`, `bool`, `str`, `None` のどれか. 欠損と無限大は `None`, リストと辞書と配列と日時とカテゴリなど数と真偽でないものは文字 (`str()`)
- `DATASET_FORMAT_VERSION`: `load_dataset` が読む列の正解のデータセットの版 (`int`. 今は 1)
- `ITEMS_FORMAT_VERSIONS`: `load_items` が読むファイルの組のデータセットの版の組 (`tuple[int, ...]`. 今は `(2, 3)`)
- `PLACEMENTS`: `load_items` が読める項目の置き方 (`dataset.yaml` の `entries.<名前>.placement`) の名前の組 (`tuple[str, ...]`. 今は `("file", "directory", "column")`. 意味は「書き出しの版 2」の `placement`). これに無い置き方の項目を持つデータセットは `load_items` が誤りで止まる
- `TRAJECTORY_FORMAT_VERSION`: `load_trajectory` が知る軌跡の説明の版 (`int`. 今は 1)
- `load_trajectory(path)`, `describe_trajectory(trajectory)`, `Trajectory`: 記録した軌跡を読み, 要約する. 形は下の「記録した軌跡」
- `load_reactions(source, user, item, time, reaction=None, loader=None, **options)`, `describe_reactions(reactions)`, `Reactions`: 並べるの反応の表を読んで約束を確かめ, 要約する. 形は下の「並べるの反応の表」
- `export_group_rows(source, path, columns, id=None, split=None, name=None, overwrite=False, loader=None, **options)`: 群分けの表を版 2 で書き出す. 形は下の「群分けの表」
- `describe_groups(source, columns=None, k=None, labels=None, seed=0, repeats=5, stability="seed", fraction=0.8, loader=None, **options)`: 学習に通さず群の要約を返す. 形は下の「群の要約」
- `read_image(path)`: ファイル 1 つの画像を numpy の配列にする低い層. 形は (高さ, 幅) か (高さ, 幅, チャンネル), 型は `uint8`, 書き込める写し. EXIF の向きを直し, パレットなどは RGB (透明があれば RGBA), 16 ビットと浮動小数は 0 から 255 に縮めた 1 チャンネル, 2 値は 0 と 255 にそろえる. 版 2 の書き出しと `load_item` の画像と同じ読み方

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 種類 (kind) | データの形. `table` (表), `timeseries` (時系列), `image` (画像), `text` (文), `pointcloud` (点群), `capture` (多視点の撮影), `audio` (音声) |
| 読み込み (loader) | ファイルかディレクトリを, ある種類のデータとして読む部品. 拡張子と中身から, 使える読み込みを選ぶ |
| データ (`Data`) | 読み込んだ結果. 全ての種類で, pandas の `DataFrame` (`frame`) を中心に持つ |
| 気付き (finding) | 分析で見つけた, 学習の前に確かめた方がよいこと (欠損の多い列, ほぼ定数の列, リークの疑い, クラスの偏りなど). 重要度 (`warning`, `info`) と理由を持つ |
| レシピ (recipe) | 前処理の手順の並び. YAML に書き, 版を付ける |
| データセット (dataset) | 前処理をして分割したデータを, 学習用に書き出したディレクトリ |
| 軌跡 (trajectory) | 強化学習で, 方策を環境で走らせた記録. 1 歩が 1 行の表 (エピソードの番号, 歩数, 観測, 行動, 報酬, 終わったか). 下の「記録した軌跡」 |
| 反応の表 | 並べる (推薦) の学習に使う, 1 行が 1 つの反応 (利用者が品物を買った, 見たなど) の表. 利用者, 品物, 時刻の列と, 任意の反応の強さの列. 下の「並べるの反応の表」 |
| 群の要約 | 群分け (まとめる) で, 群ごとの行の数, 割合, 安定性と, 群を作った列の要約 (数の列は平均, 他の列は最も多い値と割合) を並べた表. 下の「群の要約」 |
| 項目 (entry) | 版 2 のデータセットの 1 件を作る, 名前を付けた入力か正解 (画像, 領域, 撮影, 点群など). 「書き出しの版 2」 |

## 4. データの形

全ての種類で, 中心は 1 つの `DataFrame` (`frame`). 分析と前処理の多くを, 種類に依らず pandas の同じ仕組みで行うため.

| 種類 | `frame` の 1 行 | 中身 |
| --- | --- | --- |
| `table` | 1 件 | 読み込んだ表そのもの |
| `timeseries` | 1 時点 | 表と同じ. 日時の列 (`time_column`) を持ち, 時刻の順に並べる |
| `image` | 1 枚の画像 | ファイルの場所 (`path`), ラベル (クラスごとのフォルダなら `label`), 幅, 高さ, チャンネル数, 大きさ (バイト), ファイルの中身の SHA-256 (`digest`. 同じ画像を見つけるため, 読み込みで全てのバイトを読む. 大きなフォルダでは読み込みの設定 `digest: false` で省ける. 読み込みの種類の設定の一覧にも出し, 画面からの文字 (`false`, `0`, `no`) も読む) など. 画素は `load_item` で必要なときだけ読む |
| `text` | 1 つの文 | 文 (`text`), ラベル (あれば), 文字数, 語の数など |
| `pointcloud` | 1 つの点群 | ファイルの場所, 点の数, 範囲, 属性 (色, 法線) の有無など. 点は `load_item` で読む |
| `capture` | 1 回の多視点の撮影 | 撮影のディレクトリの場所, 枚数, 追跡できた枚数, 画像の大きさ, 深度の有効率と信頼度, 撮影距離, 周回の最も大きい隙間など. 各枚の画像と姿勢と深度の場所は `load_item` で読む |
| `audio` | 1 つの音声 | ファイルの場所, ラベル (クラスごとのフォルダなら), 標本化の周波数, チャンネル数, bit 数, 長さ (秒) など. 音は `load_item` で読む |

`Data` が持つもの.

- `kind`: 種類
- `frame`: 上の `DataFrame`
- `source`: 読み込んだ場所 (`path`. シンボリックリンクと `..` をたどった絶対パス), 読み込み (`loader`) の名前, 読み込みの設定 (`options`), 種類ごとの値の辞書. 他のリポジトリが頼ってよい欄は `loader`, `options`, `size`, `modified` と, 下の `root` だけ. 他の欄 (`path`, 表の `encoding`, `sep`, `sheets`, `sheet`, 撮影の `min_confidence`, `depth_read`, 撮影と音声の `capped`, 音声の `missing_reader` など) は分析が使う内側の値で, 名前と形を約束しない
    - `loader`, `options`: 読み込みの名前 (`str`) と, `load_data` に渡した設定の辞書. 頼ってよいのは, 同じデータを同じ読み方で読み直すのに要るため (ML-Quest が問題の設定の `data` に残す. ML-Fathom も同じ名前と設定で `load_data` を呼び直す. 2 章の表)
    - `size`, `modified`: `load_data` が読んだときの, 渡した場所 (リンクの先) の大きさ (`int`. バイト) と更新時刻 (`float`. 1970 年からの秒). `os.stat` の `st_size` と `st_mtime` そのもので, ディレクトリではディレクトリ自身の値 (中のファイルの合計や最新ではない. ファイルを足すか消すと変わるが, 中のファイルを書き換えても変わらない). 頼ってよいのは, 入れた後にファイルが変わったかを使う側が確かめるため (ML-Quest)
    - `root`: 1 件の場所の根. 画像 (`image_folder`), 点群 (`pointcloud`), 撮影 (`capture`), 音声 (`audio_folder`) の読み込みが入れる (表と文は持たない). 文字の絶対パスで, 今のディレクトリに依らない. 渡した場所を絶対パスにしただけで, シンボリックリンクと `..` はたどらない (`path` と違う). 絶対パスにするのは, 今のディレクトリが変わっても同じ場所を指すため. たどらないのは, 使う側が渡した名前のまま比べられ, 外を読まないことを確かめる側が `root` と `root` / `path` の両方を自分でたどって外かを判定できるため (読み込みが先にたどると, リンクで置いた根の名前が消える)
    - `frame` の `path` 列: `root` からの相対の場所 (`/` 区切り). `root` / `path` が 1 件 (画像, 点群, 音声はファイル, 撮影はディレクトリ). `<クラス>/<ファイル>` の形ならクラスのフォルダを含む. `load_item` も `root` / `path` を読む
    - ディレクトリを読んだ場合, `root` はそのディレクトリ. ファイル 1 つ (画像 1 枚, 点群 1 つ, 音声 1 つ) を読んだ場合, `root` はそのファイルのあるディレクトリで, `path` はファイルの名前. 撮影は, 1 回の撮影 (`transforms.json` を持つディレクトリ) を読んだ場合, `root` はその親で, `path` は撮影のディレクトリの名前. 撮影を並べたディレクトリを読んだ場合, `root` はそのディレクトリ
    - 読み込みが並べるのは `root` の下の場所だけ. 読み込んだディレクトリの外を読まないことを確かめる側は, `root` と `root` / `path` の両方のリンクをたどった後で比べる
    - 外を指すリンク: 画像, 文, 点群, 撮影, 音声のディレクトリの読み込みは, 中のシンボリックリンクのうち, たどった後の場所が読み込んだディレクトリ (それ自体もたどった後の場所) の下に無いものを既定で読まない. その件は表に残し, `error` に理由 (外を指すリンクであることと, 設定 `follow_links` で読めること) を書く (画像と文は `error` の列をこの場合だけ持ち, 画像の幅など, 文の `text`, `length`, `words` は欠損. 撮影の中の画像, 深度, 信頼度, 点群が外を指す場合は無いものとし, `missing_files` に数える). 分析では読めない件 (`unreadable_items`) に数える (文の空の文と同じ文には数えない). `load_item` も同じ決まりで, 外を指す件は理由付きの誤り (`ValueError`) にするので, 中身の手順と書き出しも外を読まない (表の手順 `filter_rows` (`error` が `isna`) で除く). 手元の思わぬファイル (画面から渡した場所の中のリンクの先) を読まないため
    - 中を指すリンク (たどった後も読み込んだディレクトリの下) は読む. 読み込んだディレクトリ自体がリンクの場合と, ファイル 1 つを渡した場合は, 渡したものとしてそのまま信頼する (渡した人が選んだ場所のため)
    - 読み込みの設定 `follow_links: true` (既定 `false`) では外を指すリンクの先も読む (大きなデータを共有の保存先に置き, リンクで使う場合). 読み込みの種類の設定の一覧にも出す. 設定は他の読み込みの設定と同じく `source` の `options` に残るので, 同じ設定で読み直せる. 前処理のレシピには残さない. 版 1 の書き出しの `source` には読み込みの設定の写しとして入るが, 書き出しを読む側はリンクをたどらない (書き出しは中身を写すため. 推論のときの `transform_item` はファイルを直に受け取り, 読み込んだディレクトリが無い)
    - 真偽の読み込みの設定 (`follow_links`, 画像の `digest`) と, 版 2 の書き出し, `normalize_capture`, `capture_shift` の引数 `follow_links` は, 画面からの文字も読む. `true`, `1`, `yes`, `on` は真, `false`, `0`, `no`, `off` と空は偽 (大文字と小文字, 前後の空白は区別しない). 他の文字は, 設定の名前と受け付ける値を挙げて誤り (`ValueError`. 取り違えた値で黙って読み方を変えないため)
- `roles`: 列の役割 (`target` 目的の列, `time` 日時の列, `id` 識別子の列, `text` 文の列, `path` ファイルの場所の列). 推定するか, 利用者が指定する
- `load_item(index, seconds=None)`: 画像, 点群などの 1 件の中身を読む関数 (表には無い). `seconds` は音声だけが受け取り, 先頭の `seconds` 秒だけを読む (長い録音の先頭だけを画面で見るため. 返す形は下の「音声」の `read_audio` と同じ). `None` は全てを読み, ファイルより長い秒も全てを返す. 音声以外の種類に渡すと, 理由付きの誤り (`ValueError`). 0 以下の秒, 無限, 数でない値も誤り (0 以下は空の音を返しても見たいものが無く, 画面の入力の取り違えに気付けないため. 中身の手順 `fix_length` の `seconds` と同じく 0 より大きい有限の数だけを受け取る). `read_audio` を単体で使う場合は, 0 以下の秒で空の音を返す (`load_item` は誤りにするので, ふるまいが分かれる)

大きなデータは, 分析では先頭ではなく無作為に選んだ見本 (既定 10 万行. 画像などは 2000 件) を使い, 見本で計算したことを結果に書く. 時系列は間隔を保つように等間隔に間引き, 時刻の間隔と抜けは間引く前の全体で求める.

読み込みでは, 日付の区切り (`-`, `/`, `:`, `年`) を含む値の列だけを日時の候補にする (カンマ付きの数などを日時と取り違えないように). `2024年1月3日` の書き方も日時にし, 書き方の混ざった列も読む. `1,234` の形の桁区切りの数と, 前に通貨の記号 (`¥$€£`), 後に決まった単位 (円, %, 個, kg など) の付いた数 (読めた値が全て同じ単位) は数にする (全角の数字も. マイナスは記号の前でも後でも. 単位の違う値の混ざる列, 0 で始まる値 (001件), 型番のような他の文字の付いた値は数にしない. % や 万円 は換算せず, 書いた数のまま). 日時の列の値が重なっていて, 別の列 (文字か整数, 2 から 10000 種類. 1 つの値あたり平均 10 行以上) と組にすると重ならず, その組の半分以上が埋まり, 1 割以上の時刻に 2 つ以上の値が並ぶ (店ごとの売上のような複数の系列. 注文の表の顧客のようにまばらなものと, 時刻が行ごとに違い, 重複した行だけで時刻が重なるレビューのラベルのようなものは除く) 場合は時系列とし, その列を役割 `series` に記録する. 分析では間隔と自己相関を最も長い系列で求め (`series_by`, `series_count`. 見本で分析する場合も, 間引く前の最も長い系列で), 間引く場合は時刻の値で間引いて全ての系列を残す. 順位の列 (1 位から N 位) のように, 同じ時刻に値が並ぶ数の列も系列と判定されうる (読み方で表として読むか, 時刻の列を選び直す). 列の名前は文字にそろえ, 重なる名前には番号を付ける (`name.1`).

## 5. 読み込み

読み込みは登録簿に集める (ML-ModelControl の部品の登録簿と同じ考え方). 1 つの読み込みは次を持つ.

- 名前 (`csv`, `image_folder` など), 種類, 扱う拡張子
- `sniff(path)`: その場所を読めるかと, その確からしさ (0 から 1) を返す. 拡張子だけでなく中身 (先頭の数行, ディレクトリの構成) も見る
- `load(path, **options)`: `Data` を返す
- 設定 (区切り文字, 文字コード, ヘッダーの行, 日時の列, 文の列など) の説明と既定値. `describe_loaders` の `options` に出す設定は, `load` が読む設定の名前と同じにする (一覧に無い名前を, 他のリポジトリが知らない設定として断らないため. テストで両者を比べる)

`load_data(path, loader=None, **options)` は, 指定が無ければ全ての読み込みの `sniff` で一番確からしいものを選ぶ. `detect(path, **options)` は候補を確からしさの順に返す (GUI で選び直せるように). 設定は, 読み込みが推定にも使うと決めたものだけを `sniff` に渡す (今は撮影の `follow_links`. 先頭の撮影の `transforms.json` が外を指すリンクでも, たどる設定なら撮影と推定する). `load_data` は受けた設定を `detect` にも渡す.

| 読み込み | 種類 | 対象 |
| --- | --- | --- |
| `csv` | table / timeseries | `.csv`, `.tsv`, `.txt` (区切り文字と文字コードを推定) |
| `json` | table / timeseries | `.json` (レコードの配列, 列の辞書, 入れ子は平らにする), `.jsonl` / `.ndjson` |
| `parquet` | table / timeseries | `.parquet` (pyarrow が要る) |
| `excel` | table / timeseries | `.xlsx` (openpyxl が要る) |
| `npy` | table / pointcloud | `.npy`, `.npz` (2 次元の配列は表, (N, 3 以上) で名前が点群らしいものは点群) |
| `image_folder` | image | 画像のディレクトリ (`<クラス>/<画像>` の形ならラベル付き) と画像 1 枚 (Pillow が要る). 表にはヘッダーから読んだ幅, 高さ, チャンネル数, 色の形式, 大きさ |
| `text_lines` | text | 1 行 1 文の `.txt`, `<クラス>/<文>.txt` のディレクトリ. 表には文, 文字数, 語の数 |
| `pointcloud` | pointcloud | `.ply` (ASCII とバイナリ), `.pcd` (ASCII), `.xyz` / `.pts`, `(点の数, 3 以上)` の `.npy`. 1 つのファイルか, `<クラス>/<点群>` のディレクトリ. 表には点の数, 各軸の範囲, 中心, 色と法線の有無 |
| `capture` | capture | 多視点の撮影 (`transforms.json` を持つディレクトリか, それを並べたディレクトリ). 下の「多視点の撮影」 |
| `audio_folder` | audio | 音声の 1 つのファイルか, `<クラス>/<音声>` のディレクトリ. `.wav` は標準ライブラリと numpy で, FLAC, MP3, Ogg, AIFF は soundfile で読む (soundfile が要る). 下の「音声」 |

表の中の列が日時で, 日時の順に並ぶ (か並べられる) 場合は `timeseries` と推定する. 表の中に長い文の列があり, 他に列が少ない場合は `text` の候補にもする.

### 多視点の撮影 (`capture`)

AR の端末などで物体の周りを撮った 1 回の撮影を 1 件とする. 1 件は「画像の並び, 各枚のカメラの姿勢, 深度と信頼度の画像, (あれば) 点群」のまとまりで, 1 つのファイルではない. 多視点の画像から 3D の形を作る学習の入力と, その撮影の質のばらつき (どの撮影なら使えるか) を確かめるために読む.

- 形: `transforms.json` (カメラの内部パラメータ `fl_x`, `fl_y`, `cx`, `cy`, `w`, `h` と, `frames` の各枚の `file_path` と `transform_matrix` (カメラから世界への 4 x 4)) を持つディレクトリ. 各枚の `raw_depth_file_path` (生の深度. 無ければ穴を埋めた `depth_file_path`. 16 bit の PNG. 単位は `depth.depth_format` (大文字と小文字は区別しない. millimeter, centimeter, meter. 分からなければミリ). `depth.invalid_value` (既定 0) は欠け) と `confidence_file_path` (8 bit の PNG, 0 から 255. 生の深度と組), `tracking_state`, 撮影全体の `coordinate_convention` (`world_up`, `camera_axes`, `depth` (深度の測り方. `z` か `ray`), `pixel_center` (画素の中心. 既定 0.5)), `capture.device_model`, `point_cloud.file_path` があれば使う. 無ければその列は欠損
- `transforms.json` に書かれた場所は, 撮影のディレクトリの中のファイルだけを使う (絶対パスや `..` で外を指す場所は無いものとする. 読み込みが手元の任意のファイルを読まないように). 中かは書かれた場所の文字の上で確かめ, 加えてリンクをたどった後の場所を読み込んだディレクトリ (撮影を並べたディレクトリか, 1 回の撮影) と比べる (上の「データの形」の外を指すリンク. `follow_links: true` ではたどる). 撮影のディレクトリ自体か `transforms.json` が外を指すリンクの場合は, その撮影の `error` に理由を書く (`transforms.json` も読まない)
- 列: `path` (撮影のディレクトリ), `frames` (枚数), `tracked` (追跡できた枚数. `tracking_state` が無い枚は追跡できたとする), `width`, `height`, `fl_x`, `device`, `depth_source` (`raw` 生の深度, `smoothed` 穴を埋めた深度 (欠けがほぼ無いので有効率は高く出る), `mixed`), `depth_valid` (深度の欠けでない画素の割合. 枚ごとの平均), `depth_confident` (信頼度が `min_confidence` (既定 128) 以上の画素の割合. 形の違う信頼度の画像は数えない), `distance_min`, `distance_median`, `distance_max` (枚ごとの深度の中央値 (メートル) の最小, 中央値, 最大. 背景も含む), `view_gap` (物体の中心から見たカメラの方位の, 最も大きい隙間 (度)), `points` (点群の点の数), `missing_files` (無いか外を指す画像の数), `error` (読めない理由)
- 深度, 距離, 方位は, 追跡できた枚だけで求める (追跡できなかった枚の姿勢は正しくない)
- 方位の隙間: 物体の中心は各枚の視線の直線に最も近い点 (最小二乗. 直線への距離は向きの符号に依らない). 上の向きは `world_up`, 無ければ各カメラの右の軸に最も垂直な向き (傾けずに撮れば右の軸は水平なので, 見下ろして撮っても傾かない. 符号はカメラの上の軸の平均に合わせ, `camera_axes` に OpenCV か +Z forward とあればカメラの -Y が上). 上の向きに垂直な面に写した方位の, 隣どうしの差の最大. 物の周りを回った撮影でない場合 (視線がほぼ平行で中心が決まらない, 中心が半分以上のカメラの後ろ, カメラが中心から水平に撮影距離の 1 割 (深度が無ければ 5 cm) も離れていない) は欠損にし, 気付き (`no_orbit`) を出す
- 深度は Pillow で読む (無ければ深度の列は欠損にし, 気付きに書く). 画像の画素は読まない (大きさは `transforms.json` の `w`, `h`)
- `capture_layout(item, distance=None)` は, 1 回の撮影のカメラを物の中心から上から見た配置 (各枚の面の上の位置 (メートル), 追跡できたか, 最も大きい隙間とその始まりの方位) にする (画面で周回の欠けを描くため. 回った撮影でなければ位置は None. 表の `view_gap` と同じ判定にするには, `distance` に表の `distance_median` を渡す. 方位は上から見て反時計回り (y は上向きの座標. y が下向きの画面の座標では y を反転して描く))
- `load_item(i)` は, 内部パラメータ, 各枚 (画像, 生の深度, 穴を埋めた深度, 信頼度の場所 (撮影のディレクトリの中にある場合だけ. 無ければ None), 4 x 4 の姿勢, 追跡の状態), 点群の場所, 座標の決まりの辞書を返す
- 気付き: 読めない撮影 (`unreadable_items`), 追跡できなかった枚 (`tracking_lost`), 無いか外を指す画像 (`missing_files`), 深度の信頼度の低い撮影 (`low_depth_confidence`. 信頼できる画素が 3 割未満. 深度の 1 画素より細い物や遠い物は信頼度が落ちる), 周回の大きな欠け (`view_gap`. 90 度以上), 回った撮影と見なせない (`no_orbit`), 画像の大きさがそろわない (`mixed_sizes`), 撮影が上限 (1 万件) を超えた (`too_many_files`), Pillow が無い (`missing_reader`)
- 版 1 の前処理と書き出しは対象外 (`prepare` は誤り. 撮影は 1 行の列の正解に収まらない). 撮影と正解の点群の対は, 版 2 の約束で書き出す (`export_capture_clouds`. 下の「書き出しの版 2」)

### 音声 (`audio_folder`)

音の分類や認識の学習の入力を, 中身を確かめてから使うために読む.

- WAVE: `.wav`, `.wave` の PCM (8, 16, 24, 32 bit) と 32 bit の浮動小数 (拡張の形式 `WAVE_FORMAT_EXTENSIBLE` の中の形式も). 標準ライブラリと numpy だけで読む (よく使う形式を任意の依存なしで読むため). 他の形式の番号 (A-law など), `data` か `fmt` の欄の無いファイル, 1 つの標本の組のバイト数 (block align) がチャンネル × バイト数より小さいファイルは, 読めない理由をその行の `error` に書く
- 他の形式: FLAC (`.flac`), MP3 (`.mp3`), Ogg の Vorbis と Opus (`.ogg`, `.opus`), AIFF (`.aif`, `.aiff`) は soundfile (libsndfile を包む. 任意の依存 `[audio]`) で読む. soundfile は BSD, libsndfile と MP3 の復号 (mpg123) は LGPL で, 商用でも使える. MP3 は libsndfile 1.1 以上で読める (`soundfile>=0.12` の wheel が持つ libsndfile は 1.1 以上). MP3 を読めない古い libsndfile の場合は, MP3 の行の `error` に libsndfile の版と理由を書く
    - bit 数と形式は libsndfile の中身の形式 (subtype) から決める. `PCM_S8`, `PCM_U8`, `PCM_16`, `PCM_24`, `PCM_32` は `pcm` と 8, 16, 24, 32 bit, `FLOAT` と `DOUBLE` は `float` と 32, 64 bit. 他 (MP3, Vorbis, Opus, μ-law, ADPCM など) は `compressed` とし, bit 数は欠損 (圧縮した形式は復号の後の bit 数を持たないため)
    - soundfile が無い場合: その形式の行の `error` に soundfile が要ることを書き (表の手順 `filter_rows` で除ける), 気付き `missing_reader` (info) を出す. 1 つのファイルか, ディレクトリの全ての音声がその形式の場合は, 読める件が無いので導入の仕方を添えた誤り (`ImportError`)
- 列: `path`, `label` (`<クラス>/<音声>` の形の場合), `sample_rate` (1 秒の標本の数), `channels`, `bits` (`compressed` では欠損), `format` (`pcm`, `float`, `compressed`), `frames` (標本の数), `duration` (秒), `bytes`, `error` (読めない理由). 読み込みではヘッダーだけを読む (中身の欄 `data` は読まない. 書かれた大きさがファイルより長い書きかけのファイルは, ある分だけ)
- `load_item(i)` と `read_audio(ファイル)` は `samples` ((標本の数, チャンネル) の float32. 整数の形式は満点 (16 bit なら 32768) を 1 にそろえる (-1 から 1 未満). 浮動小数はそのままの値. 8 bit は符号なしなので 128 を 0 にする) と `sample_rate` の辞書を返す (soundfile で読む形式も同じ形. libsndfile も整数の形式を満点で割る). `read_audio(ファイル, seconds)` と `load_item(i, seconds)` は先頭の `seconds` 秒だけを読む. 値は float32 のまま求める (16 bit のステレオで, ファイルの約 3 倍の記憶)
- 分析 (`items`): 件数, 読めない数, 標本化の周波数とチャンネル数の分布, 長さ (秒の最小, 中央値, 最大, 合計), 見本 (無作為な最大 200 件. 1 件は先頭の 30 秒だけを読む. 長い録音で記憶を使いすぎないため. 長さなどの表の値はヘッダーから全体で求める) の音の大きさ (RMS と最大の振幅の中央値), ほぼ無音の数 (RMS が 0.001 (約 -60 dBFS) 未満), 割れた数 (下の「音の割れ」)
    - 音の割れ: 標本の 1 % 以上が, 形式の満点の端に張り付いた音声を数える
    - 端の値: 整数の形式は正の最大の値 (2^(b-1) - 1) / 2^(b-1) 以上の振幅 (8 bit は 127 / 128, 16 bit は 32767 / 32768. 負の端 -1 も含む). 浮動小数と `compressed` は 1 以上の振幅 (1 を超える値は, 整数の形式に直すか再生すると割れるため. 割れた音を圧縮すると, 復号した波は割れた所で 1 を超える)
    - 端を bit 数ごとに決めるのは, 全ての bit 数で 127 / 128 にすると, 16 bit 以上の割れていない大きな音 (最大 0.995 の正弦波など) も割れと数えるため
    - 端に張り付いた標本の割合だけで見る. 音量を下げた後の割れ (端より低い所で平らな波形) と, 標本の 1 % に満たない短い割れは見ない
- 気付き: 読めないファイル (`unreadable_items`. soundfile が無くて読めない件は除く), soundfile が無くて読めない形式がある (`missing_reader`. info), 標本化の周波数かチャンネル数がそろわない (`mixed_sizes`), 長さが 2 倍以上ばらつくか, 長さ 0 の音声と長さのある音声が混ざる (`mixed_lengths`. info), ほぼ無音 (`silent_items`), 音が割れている (`clipped_items`. info), ファイルが上限を超えた (`too_many_files`)
- 前処理と書き出し: 画像, 文, 点群と同じく, 表の手順で件を絞ってから中身の手順 (`item_steps`. 下の「前処理のレシピ」の音声の手順) で 1 件ずつ (チャンネル, 標本の数) の float32 の配列にし, `export_dataset` が版 1 で書く (`kind: audio`, `train_items.npy` は (件数, チャンネル, 標本の数)). 全ての件の形をそろえるには, 標本化の周波数 (`resample`), チャンネル (`mix_channels`), 長さ (`fix_length`) の 3 つをそろえる. 読めない件は表の手順 `filter_rows` (`error` が `isna`) で除く. `prepare(read_items=False)` は読み込みの表から, そろえる手順の無いまま周波数, チャンネル数, 長さがそろわないことを注意 (`notes`) にする (`resample` があれば長さは秒で比べる). 推論のときは `transform_item` に音声のファイルの場所か `read_audio` の辞書を渡すと, 学習のときと同じ (チャンネル, 標本の数) の配列を返す

### 記録した軌跡 (`load_trajectory`)

強化学習の方策を走らせた軌跡を, 1 歩が 1 行の表で読み, エピソードの数, 長さ, 報酬の和, 観測と行動の値, 守りの結果, 行動を選んだ確率を要約する. ML-Found が評価のときに書く軌跡と, 利用者の手元の表を同じ口で読む. 読み込みの登録簿には入れない (`load_data` は軌跡の CSV を普通の表として読む).

- `load_trajectory(path)`: `path` は表 (`<名前>.csv` か `<名前>.parquet`) か, 説明 (`<名前>.json`. その `file` の表を読む. `file` は同じディレクトリの `.csv` か `.parquet` の名前だけ). 表を渡した場合は, 隣に `<名前>.json` があれば説明として読む. 無ければ説明の無い表として読む (利用者の表). 隣の説明の `file` が表の名前と違う場合は, 別の表の説明なので使わず, 気付きに書く
- 表の列 (ML-Found の `docs/FORMAT.md` の「trajectories」と同じ名前と意味)

| 列 | 型 | 要るか | 中身 |
| --- | --- | --- | --- |
| `episode` | 整数 (空は誤り) | 要る | エピソードの番号 |
| `step` | 整数 (空は誤り) | 要る | エピソードの中の歩の番号 |
| `obs` か `obs_<番号>` | Discrete は整数, 他は数 (形の合わない観測と数でない観測は, 全ての観測の列が空) | 要る | 行動を選ぶ前の観測. 1 つの値は `obs`, 並びは平らにした要素ごとに `obs_0`, `obs_1`, ... |
| `action` か `action_<番号>` | Discrete は整数, 他は数. 空もある | 要る | 環境に渡した行動. 守りで止めた判断の行は空 |
| `reward` | 数か空 | 要る | 行動の後の報酬. 守りで止めた判断の行は空 |
| `terminated`, `truncated` | 真偽値 (空は誤り) | 要る | 終了の歩か, 打ち切りの歩か |
| `seed` | 整数か空 | 任意 | エピソードを始めた乱数の種 |
| `guard`, `guard_reasons` | 文字 | 任意 | 守りの結果 (`ok`, `clipped`, `fallback`, `stop`, `handover`) と, 働いた理由 (`; ` でつなぐ. 働かなければ空) |
| `action_prob` | 数か空 | 任意 | 記録した方策が, その観測でその行の行動を選んだ確率 (0 より大きく 1 以下). 守りで止めた判断の行は空 |

- **観測と行動の列は名前で見分ける**: `obs` か `obs_<番号>` (番号は 0 か, 0 で始まらない 10 進), `action` か `action_<番号>`. 番号の列は番号の順に並べる (表の列の並びに依らない). 同じ表に `obs` と `obs_<番号>` が並ぶ場合と, どちらも無い場合は誤り. 番号が 0 から続かない場合は気付きに書く. 説明の `observation_columns` と `action_columns` は使わず, 名前で見分けたものと違えば気付きに書く
- **守りの列**: `guard` の列がある表を守りのある表とする (`guarded`). 説明の `guarded` と違えば気付きに書く. `guard` が `stop` か `handover` の行は, 行動と報酬が空で, 環境を進めていない
- **確率の列**: `action_prob` の列がある表を確率のある表とする (`with_action_prob`). 説明の `with_action_prob` と違えば気付きに書く (説明に項目が無ければ表の列で決める). 範囲の外の値 (0 以下, 1 を超える値, nan, 無限大) は誤りにせず読み, 要約で数えて気付きに書く
- **知らない列は残す**: 上の他の列も表に残し, 型を決めて読む. 要約では `extra_columns` に並べる
- **型の決め方**: 説明の `types` (`integer`, `number`, `boolean`, `string`. 他の値は使わず気付きに書く), 上の列の名前で決まった型, 値から決めた型の順. 値から決める場合は, 全ての空でない値が読める型を, 真偽値, 整数, 数, 文字の順に選ぶ (値の無い列は数). 説明の型で読めない列は, 表を使う決まりに合わせて名前で決まった型か値から決めた型で読み直し, 気付きに書く. 観測, 行動, 報酬, 確率が整数か数でない場合と, 値が型の書き方でない場合は, 列の名前と値を挙げて誤り. 整数は int64 に入るものだけ (入らない値は誤り)
- **CSV の値**: UTF-8 (先頭の BOM は除く) で, 1 行目が見出し. 空の値だけが欠け. `nan`, `inf`, `-inf` は数の値で, 欠けにしない. 真偽値は `true` か `false` (大文字と小文字は区別しない). 見出しの列の名前が重なる表と, 値の数が見出しと違う行のある表は誤り
- **Parquet**: 同じ列の名前で, 真偽値, 整数, 浮動小数の型の列を読む (整数の列は数としても読む). 文字の型の列は CSV と同じ読み方. pandas で書いた表も読めるように, 全て null の型の列は欠けだけの列として決まった型 (決まらなければ数) で読み, 値が全て整数の浮動小数の列は整数の列 (`episode`, `step`, `seed` など) としても読む (pandas は欠けのある整数を浮動小数で書くため). 0 と 1 の整数の `terminated`, `truncated` は真偽値として読まず誤り (真偽値の型で書く). 行の数は 400 万まで (64 MiB の CSV の最も短い行と同じ程度. 超えるものは読まない). null が欠けで, nan は値 (pandas を通さず pyarrow で読み, 欠けと nan を分ける). pyarrow が要る (任意の依存 `[parquet]`. 無ければ導入の仕方を添えた `ImportError`)
- **表の型**: 欠けの無い列は numpy の型 (`int64`, `float64`, `bool`) か文字の `object`. 欠けのある列は pandas の欠けを持てる型 (`Int64`, `Float64`, `boolean`) か `None` を持つ `object`. `Float64` は nan を欠けと別の値として残す. numpy の `float64` の列には欠けが無いので, その nan は値 (pandas の `isna` は nan も真にするので, 欠けは列の型で見分けるか, 要約の `missing` を使う). `guard_reasons` の空は空の文字
- **行の順**: エピソード, 歩の順でない表は, 同じ番号の行の順を保って並べ直し, 気付きに書く. 同じエピソードの同じ歩の行が重なる場合も気付きに書く
- **説明**: 版 (`format_version`) が 1 以上の整数でない説明, JSON の辞書でない説明, リンク, 普通でないファイル, 1 MiB を超える説明は, 理由を気付きに書いて使わない (説明の無い表として読む). 説明を `path` に渡した場合は, 同じものを誤りにする. 知っている版 (`TRAJECTORY_FORMAT_VERSION`) より新しい説明は, 読める項目だけを使い, 新しい版の ML-Found の出力であることを気付きに書く. 説明の `columns`, `rows`, `episodes` が表と違えば, 表の方を使い気付きに書く (気付きに書く値は 80 文字までに切る)
- **読むファイル**: 表も説明も普通のファイルだけ. シンボリックリンクは辿らずに誤り (説明は使わない), FIFO などは待たずに誤り. 表は 64 MiB, 説明は 1 MiB まで (超えるものは読まない. 大きさは開いたファイルで確かめる)
- `Trajectory` の欄: `name` (表のファイルの名前から拡張子を除いたもの), `format` (`csv` か `parquet`), `frame` (型の値の表), `types` (列ごとの型), `observation_columns`, `action_columns` (要素の順), `guarded`, `info` (説明の辞書か None), `notes` (気付きの日本語の文の並び), `with_action_prob` (確率の列があるか)

`describe_trajectory(trajectory)` は JSON にできる辞書を返す (nan と無限大は None). 鍵は次のとおり.

| 鍵 | 中身 |
| --- | --- |
| `name`, `format`, `described` | 軌跡の名前, 表の形式, 説明を使ったか |
| `format_version`, `source`, `env`, `epoch`, `description`, `complete`, `dropped_episodes`, `observation_space`, `action_space` | 説明の同じ名前の項目 (説明が無いか項目が無ければ None) |
| `rows`, `episodes`, `steps` | 行の数, エピソードの数, 環境を進めた歩数 (報酬のある行の数) |
| `columns` | 列ごとの `{"name", "type"}` の並び (表の列の順) |
| `observation_columns`, `action_columns`, `extra_columns` | 観測と行動の列 (要素の順) と, 上の表に無い列 |
| `guarded` | 守りの列があるか |
| `with_action_prob` | 行動を選んだ確率の列があるか |
| `length`, `return` | エピソードごとの歩数と報酬の和の `min`, `max`, `mean`, `std` (標本の標準偏差. 1 つなら 0), `median`. 報酬の和は, 和が有限のエピソードだけで求める |
| `unknown_returns` | 報酬に nan か無限大を含み, 和が有限でないエピソードの数 |
| `ends` | 終わり方ごとのエピソードの数 (`terminated`, `truncated`, `stop`, `handover`, `open`) |
| `observations`, `actions` | 列ごとの `name`, `type`, `missing` (空の数), `nan`, `infinite`, 有限の値の `min`, `max`, `mean`, `std`, `median`, `counts` (整数の列で, 異なる値が 50 以下なら `{"value", "count"}` の並び. 他は None) |
| `guard` | 守りの列のある表で, `results` (結果ごとの行の数. 知らない結果もそのまま数え, 空は `missing`) と `reasons` (理由ごとの `{"reason", "count"}` の並び. 多い順). 守りの列が無ければ None |
| `action_prob` | 確率の列のある表で, `missing` (空の数), `out_of_range` (0 より大きく 1 以下でない値の数. nan と無限大も含む. 1 件以上なら `notes` にも書く), 範囲の中の値の `min`, `max`, `mean`, `std`, `median`. 確率の列が無ければ None |
| `per_episode` | エピソードごとの `episode`, `rows` (行の数), `length` (報酬のある行の数), `return` (報酬の和. 空を除き, 有限でなければ None), `end`, `seed` (最初の行の種か None) の並び (エピソードの順. 先頭の 1000 件まで) |
| `per_episode_truncated` | エピソードが 1000 件を超え, `per_episode` を切ったか (切った場合は `notes` にも書く. 他の鍵の値は全てのエピソードで求める) |
| `notes` | `Trajectory` の `notes` と, 要約で気付いたこと |

- エピソードの歩数と報酬の和は, 報酬のある行で求める (守りで止めた判断の行は環境を進めていない). ML-Found の評価の行 (`length`, `reward`) と同じ値になる
- 終わり方は最後の行で決める. `guard` が `stop` か `handover` ならそれ, 次に `terminated` が真なら `terminated` (`truncated` も真の場合を含む), `truncated` が真なら `truncated`, どれでもなければ `open` (利用者の表の, 終わりの印の無いエピソード)

### 並べるの反応の表 (`load_reactions`)

並べる (推薦) の学習に使う, 1 行が 1 つの反応の表を読み, 約束を確かめて, 利用者, 品物, 反応の数, 偏り, 時刻の範囲, 除いた行を要約する. 形は ML-Quest の並べるの骨組みが読む反応の表と同じで, 除く行の決まりも骨組みの学習のスクリプトと同じにする (画面で見せた数と学習の `train.log` の数が合うように). 読み込みの登録簿には入れない (表は `load_data` で普通の表として読む).

- `load_reactions(source, user, item, time, reaction=None, loader=None, **options)`: `source` は表のファイルか, `load_data` で読んだ `Data`. ファイルは `load_data(source, loader=loader, **options)` で読む (骨組みが問題の設定の読み方 `data.loader` と `data.options` で読むのと同じ). `Data` を渡した場合は, その表と読み方 (`Data.source`) を使い, `loader` と `options` を渡すと誤り. `user`, `item`, `time` は問題の設定で答えた列の名前 (ML-Quest の `ml.parts.<n>.rank` の `user`, `item`, `time`), `reaction` は反応の強さの列 (答えていなければ None)
- **列**: 4 つの役割に同じ列を渡した場合, 要る列の名前が None の場合, 表に列が無い場合, 表に同じ名前の列が 2 つ以上ある場合は誤り. 他の列は読まない
- **時刻**: 数の型の列は数のまま (`time_kind` は `number`). 他は日時として読み (`datetime`), 日時として読めない値は欠けにする. 欠けでない値があり, どれも読めない列は誤り
- **除く行**: 利用者, 品物か時刻の欠けた行 (日時として読めない時刻を含む) を除き, 次に, 反応の強さの列があれば, 強さが 0 以下か数でない行を除く (強さを渡さなければ全ての行を反応とみなす). 除いた数は 2 つに分けて数え, 1 行以上なら気付きに書く. 同じ利用者と品物の行が何行あってもよい
- **分割は持たない**: 反応の表はデータセット (`dataset.yaml` と分割ごとのデータ) にせず, ファイル 1 つのまま骨組みに渡す. 分割は骨組みが時刻で行う (反応を時刻の順に並べ, 古い反応を学習用, 新しい反応を検証用とテスト用にする). 並べるの分割は時刻で全体を切るのが決まりで, 割合は骨組みの config で変えるので, データセットの側で分けると決まりが 2 か所に分かれるため. 書き出しの前処理 (レシピ) もかけない
- `Reactions` の欄: `frame` (残した反応の表. 列は `user`, `item`, `time` と, 強さがあれば `reaction` (float). 時刻の順で, 同じ時刻は元の行の順), `columns` (役割から元の列の名前. 強さが無ければ `reaction` は None), `time_kind` (`number` か `datetime`), `rows` (除く前の行の数), `dropped_missing` (欠けで除いた行の数), `dropped_not_positive` (強さで除いた行の数), `unreadable_time` (欠けでない値のうち, 日時として読めなかった時刻の数), `source` (読み込んだ場所と読み方. `Data.source`), `notes` (気付きの日本語の文の並び)

`describe_reactions(reactions)` は JSON にできる辞書を返す (nan と無限大は None). 鍵は次のとおり.

| 鍵 | 中身 |
| --- | --- |
| `columns` | 役割 (`user`, `item`, `time`, `reaction`) から元の列の名前 |
| `source` | 読み込んだ場所と読み方 (`Data.source`) |
| `rows`, `reactions` | 除く前の行の数と, 残した反応の数 |
| `dropped` | `missing` (欠けで除いた行), `unreadable_time` (`missing` のうち, 日時として読めなかった時刻), `not_positive` (強さが 0 以下か数でない行), `total` (`missing` と `not_positive` の和) |
| `users`, `items` | 残した反応の利用者と品物の数 |
| `pairs`, `repeated` | 異なる利用者と品物の組の数と, 同じ組の 2 行目からの数 (`reactions` − `pairs`) |
| `density` | `pairs` を利用者の数 × 品物の数で割った値 (反応が無ければ None) |
| `per_user`, `per_item` | 利用者ごとと品物ごとの反応の数の `min`, `max`, `mean`, `std` (標本の標準偏差. 1 つなら 0), `median`, `once` (1 回だけの数) と, `bins` (区切り 1, 2, 3–5, 6–10, 11–20, 21–50, 51–100, 101 以上ごとの `{"from", "to", "count"}` の並び. `to` は含み, 最後は None) |
| `popularity` | 品物の人気の偏り. `top_items` (反応の多い上位 10% の品物の数. 切り上げ), `top_share` (その品物の反応の割合. 反応が無ければ None), `gini` (品物ごとの反応の数のジニ係数. 0 はどの品物も同じ数で, 1 に近いほど偏る. 品物が無ければ None), `popular` (多い順の先頭 10 件の `{"item", "reactions"}`. 品物の値は数, 真偽値, 文字はそのまま, 他は文字) |
| `time` | `kind` (`number` か `datetime`), `min`, `max` (日時は ISO 8601 の文字. 反応が無ければ None), `distinct` (異なる時刻の数) |
| `reaction` | 残した反応の強さの `min`, `max`, `mean`, `std`, `median`. 強さの列が無ければ None |
| `notes` | `Reactions` の `notes` と, 要約で気付いたこと (反応が残らない, 利用者か品物が 1 つだけで並べて確かめられない) |

## 6. 分析

`profile(data, target=None)` は JSON にできる辞書を返す.

- **概要**: 種類, 行数, 列数, メモリ, 重複した行, 見本を使ったか
- **列ごと**: 推定した型 (`numeric`, `categorical`, `boolean`, `datetime`, `text`, `id`, `constant`), 欠損の数と割合, 異なる値の数, 数値なら平均, 標準偏差, 分位点, 歪度, 外れ値 (四分位範囲の 1.5 倍の外) の数, ヒストグラム (値の幅が浮動小数の誤差ほどしかない列は, 全て同じ値の列と同じく範囲を ±0.5 に広げる). カテゴリなら頻度の上位. 文なら長さの分布. 日時なら範囲と間隔
- **列の間**: 数値の列の相関 (Pearson と Spearman), カテゴリの列の関連 (Cramér の V)
- **目的の列との関係** (`target` がある場合): 目的の列の分布 (分類ならクラスの割合), 各列と目的の列の関連の強さ (数値と数値は相関, 数値とカテゴリは相関比, カテゴリとカテゴリは Cramér の V) の順位
- **時系列** (`timeseries`): 時刻の間隔 (最も多い間隔, 抜けと重なり), 範囲, 列ごとの自己相関 (周期の候補), 移動平均と傾向
- **種類ごと**: 画像は大きさとチャンネルの分布, 壊れたファイル. 文は長さ, 語彙, 頻出語. 点群は点の数, 範囲, 属性. 多視点の撮影は枚数, 深度の有効率と信頼できる割合, 撮影距離 (上の「多視点の撮影」). 音声は標本化の周波数, 長さ, 音の大きさ (上の「音声」)
- **気付き**: 下の表

| 気付き (`code`) | 内容 |
| --- | --- |
| `high_missing` | 欠損が多い列 (30 % 以上) |
| `constant` | 値が 1 つしか無い列 |
| `near_constant` | 最も多い値が 95 % 以上の列 |
| `id_like` | 全て異なる値で, ID らしい列 (学習に使うと覚えるだけになる) |
| `duplicate_rows` | 全く同じ行 |
| `high_cardinality` | 異なる値がとても多いカテゴリの列 |
| `skewed` | 歪度が大きい数値の列 (対数を取るなどの候補) |
| `outliers` | 外れ値の多い数値の列 |
| `high_correlation` | とても強く相関する数値の列の組 (どちらかで足りる) |
| `target_leak` | 目的の列とほぼ同じ情報を持つ列 (リークの疑い) |
| `class_imbalance` | 分類の目的の列のクラスの偏り |
| `target_missing` | 目的の列の欠損 |
| `irregular_interval` | 時系列の時刻の間隔の抜けや重なり |
| `mixed_sizes` | 大きさやチャンネル数がそろわない画像, 標本化の周波数かチャンネル数がそろわない音声 |
| `unreadable_items` | 読めない画像, 点群, 音声のファイル, 読めない撮影, 外を指すリンクで読まなかった文 |
| `invalid_points` | 座標が数でない点 (NaN, inf) を含む点群 |
| `duplicate_items` | 同じ文か, 中身が同じ画像 (分割をまたぐと検証が甘くなる) |
| `empty_items` | 空の文 |
| `group_overlap` | グループの列 (`split.column`) の同じ値が複数の分割にまたがる (`prepare` が分割の後に出す. 「前処理のレシピ」) |
| `item_overlap` | 同じ画像が複数の分割にまたがる (`prepare` が分割の後に出す) |
| `panel_series` | 時系列で, 店ごとのように複数の系列が同じ時刻に並ぶ (lag の `by` で系列ごとにずらす) |
| `mixed_forms` | 表記 (全角と半角, 大文字と小文字, 前後の空白) だけが違うカテゴリの値 (目的の列でも出す) |
| `tracking_lost` | 多視点の撮影に, 追跡できなかった枚がある |
| `missing_files` | 多視点の撮影の `transforms.json` にある画像が無いか, 撮影のディレクトリの外を指す |
| `low_depth_confidence` | 多視点の撮影で, 信頼できる深度の画素が 3 割未満 |
| `view_gap` | 多視点の撮影で, 物の周りを回った方位に 90 度以上の隙間がある |
| `no_orbit` | 多視点の撮影が, 物の周りを回った撮影と見なせない (方位の隙間を求めない) |
| `too_many_files` | ファイル (や撮影) が上限を超え, 先頭だけを読んだ |
| `missing_reader` | 読むのに要るライブラリ (Pillow, soundfile など) が無く, 一部の列か件を読んでいない |
| `mixed_lengths` | 音声の長さが 2 倍以上ばらつく |
| `silent_items` | ほぼ無音の音声がある (見本で) |
| `clipped_items` | 音が割れている音声がある (見本で) |
| `multiple_sheets` | Excel に他のシートがある (読み込みの `sheet` で選ぶ. 無い番号や名前は誤り. `source` と概要の `sheets` に全ての名前, `sheet` に読んだシート) |

画像, 文, 点群, 音声では読み込みの表の列 (場所, 幅, 点の範囲, 長さなど) を学習に使わない (中身を配列にする) ので, 列の気付きは目的の列についてのもの (`class_imbalance`, `target_missing`, 目的の列の `mixed_forms`) だけを出す.

表の読み込み (csv, json, parquet, excel) は `text_column` で文の列を指定すると, 文のデータ (1 行が 1 つの文. 他の列も残し, `length` と `words` を足す (名前が重なれば番号を付け, 役割 `length`, `words` に記録). 欠損の文は空の文) として読む. 文の列は中身として読むので, 表の手順で書き換えると誤りにし (行を絞る手順は使える), 表記のゆれは中身の手順の `normalize_text` でそろえる. 書き出したデータセットの `text_column` に文の列の名前を残す (新しい表からこの列を取り出して `transform_item` に渡す). 日時の列があっても時系列にはしない. `kind: table` で, 日時の列があっても表として読む.

文のデータの分析 (`items.tokenizers`) では, 文を区切る単位の候補 (文字, 語, 部分語) を同じ物差しで比べ, `vocabulary` の引数を勧める. 文の区切り方は言語や書き方で向き不向きが大きく (英語を文字で区切ると並びが長くなり, 語で区切ると語彙に無い語が増える. 日本語は語で区切っても漢字とかなは 1 文字ずつ), 測って決める.

- 見本 (最大 5000 件の空でない文) を無作為に 8 対 2 に分け, 8 割で語彙を作り, 2 割で測る (2 割が 10 件に満たない場合は, 語彙を作った文で測り, その旨を `notes` に書く). 部分語は語彙の大きさの上限を 500, 2000, 8000 の 3 つで作る (文字の種類より十分に大きいものだけ. 文が少なく同じ語彙になれば 1 つに)
- 測るもの: 語彙の大きさ, 1 つの文のトークンの数 (平均と 95 % 点), 語彙に無いトークンの割合 (2 割の文で), 勧める長さで切られる文の割合
- 勧め方: 語彙に無いトークンが 1 % 以下の候補を語彙の小さい順にたどり, 95 % 点が今の候補より 2 割以上短くなる場合だけ大きい語彙に移る (語彙が大きいほど埋め込みが大きく, 少ないデータでは学びにくいため). 全ての候補が 1 % を超える場合は, 最も少ないもの. 勧めた理由 (`reason`) は画面に出す. 長さは 95 % 点を 8 の倍数に切り上げる (512 まで)
- `tokenizers` が入っていない場合は部分語の候補を除き, その旨を `notes` に書く

気付きは `{severity, code, message, columns}` の辞書. `message` は日本語で, 理由と次にできること (前処理の手順の候補) を書く.

### 群の要約 (`describe_groups`)

群分け (まとめる) で, 学習に通さずに分析の段階で群を作り, 群の要約を返す. 群の行の形は ML-Quest のまとめるの骨組みが `evaluations/group_summary.json` に書く行と同じにする (画面で学習の前と後の群を同じ表で見せられるように). 群は, 骨組みと同じ符号化をかけた列の特徴を, そのまま k-means で分けたもの (骨組みの比べる相手「列の特徴をそのまま k-means で分けた群」と同じ作り方).

- `describe_groups(source, columns=None, k=None, labels=None, seed=0, repeats=5, stability="seed", fraction=0.8, loader=None, **options)`: `source` は表のファイル (`load_data(source, loader=loader, **options)` で読む), `load_data` で読んだ表の `Data` (`loader` と `options` を渡すと誤り), `export_group_rows` で書き出して `load_items` で読んだデータセット (受け持ちが `group` でなければ誤り. 全ての分割の件を表の順に使う) のどれか. `columns` は群を作る列 (問題の設定で答えた列. データセットでは省くと入力の項目の全て). 表と時系列でないデータは誤り
- **列**: 列が無い, 同じ列を 2 回渡した, 表に同じ名前の列が 2 つ以上ある, 名前が群の要約の鍵 (`group`, `rows`, `share`, `stability`) か 1 件の鍵 (`id`, `split`) と同じ場合は誤り (骨組みも群の要約の鍵と同じ名前の列で止まる)
- **符号化**: 骨組みと同じ. 数の列 (真偽値を除く) は平均と標準偏差 (母の標準偏差. 散らばりが無ければ 1) で標準化し, 欠けた値は 0. 他の列は値ごとの 0 と 1 の列 (値は文字にし, 欠けた値も `(欠損)` という 1 つの値. 値は初めて出た順). 骨組みは学習用の行で符号化を決めるが, ここは分割しないので全ての行で決める. 符号化した行の幅 (数の列の数と, 種類の列ごとの値の数の和) が 1000 を超えれば, 符号化の表を作る前に誤り (値の多い種類の列を外すよう案内する. `labels` を渡した場合も同じ)
- **群**: `labels` を省くと, k-means++ で中心を置いて Lloyd 法 (100 回まで) で求めることを置き方を変えて 5 回繰り返し, 二乗距離の和の最も小さいものを使う (乱数は `seed`). `k` は 2 以上の整数で行の数まで (`labels` を省くと要り, 渡すと誤り). `labels` に行ごとの群の並びか表の群の列の名前を渡すと, その群を使う (ML-Quest の骨組みの `group_assignments.csv` の `group` など. 長さが行の数と違うか欠けがあれば誤り. 群の値の小さい順に並べる)
- **安定性**: k-means で作った群だけ, `repeats` 回 (1 以上の整数) 作り直し, 全ての行の割り当ての調整ランド指数と, 群ごとに作り直した群のうち最も重なる群との Jaccard 係数を数える. 数え方 `stability` は ML-Quest の問題の設定の答え `group.stability` と同じ値で, 骨組みが学習の後に数える数え方と同じ. 他の値は誤り (`labels` を渡した場合も確かめる. `labels` では安定性を数えないので `stability` と `fraction` は使わない)
  - `seed` (既定): 作り直すたびに種を変え (`seed + 1 + 回の番号`), 全ての行で k-means をかけ直す
  - `sample`: 作り直すたびに種を変えた乱数 (`seed + 1 + 回の番号`) で, 全ての行から `fraction` の割合 (`max(k, int(行の数 × fraction))` 行. 戻さずに引く) を引き直し, その行で k-means をかけ, 全ての行を近い中心に割り当てる. 引く行と中心の置き方は同じ乱数から続けて取る. 骨組みは学習用の行から引くが, ここは分割しないので全ての行から引く. `fraction` は 0 より大きく 1 以下の数で, 他は誤り (骨組みの `group.fraction` の既定と同じ 0.8). `seed` では使わず, 確かめない (None でもよい)
  - どちらも調整ランド指数と Jaccard 係数は引いた行だけでなく全ての行の割り当てで比べる
- **まとまり**: 全ての行 (2000 行より多ければ無作為に選んだ行. 選ぶ乱数は `seed` から作り直す. 骨組みと同じ) の, 符号化した空間でのシルエット係数. 群が 1 つなら 0

JSON にできる辞書を返す (nan と無限大は None). 鍵は次のとおり.

| 鍵 | 中身 |
| --- | --- |
| `method` | `kmeans` (列の特徴をそのまま k-means で分けた) か `labels` (渡した群) |
| `k`, `rows` | 群の数と行の数 |
| `columns` | 群を作った列の `numeric` (数の列) と `categorical` (他の列) の名前の並び |
| `width` | 符号化した行の幅 |
| `seed` | k-means の乱数の種 (`labels` では None) |
| `groups` | 群の要約の行の並び (下) |
| `stability` | `method` (数え方の `seed` か `sample`), `repeats`, `fraction` (`sample` で引く割合. `seed` では None), `ari` (調整ランド指数の平均), `ari_min` (最も低い値). `labels` では None |
| `silhouette` | シルエット係数 |
| `source` | 読み込んだ場所と読み方 (`Data.source`. データセットでは説明の `source`) |
| `notes` | 気付きの日本語の文 (欠けた値のある行の数, 行の数の半分より多い種類の値を持つ列, 行の無い群, 群が 1 つだけ) |

**群の要約の行** (`groups` の 1 つ. ML-Quest の骨組みの `evaluations/group_summary.json` の行と同じ鍵と順と値): `group` (k-means では 0 から始まる群の番号, `labels` では群の値), `rows` (行の数), `share` (全ての行に対する割合), `stability` (群ごとの Jaccard 係数の平均. `labels` と行の無い群は None) と, 群を作った列ごとの要約 (列の名前が鍵. 数の列は平均で, 値が無ければ None. 他の列は最も多い値と割合の文 (`east (100 %)`. 割合は百分率を整数に丸める). 行の無い群は None). 群の順に並べ, 最後に全ての行の行 (`group` は `全体`, `stability` は None) を置く.

## 7. 前処理のレシピ

前処理は手順の並び (レシピ) で書く. 手順は登録簿に集め, 種類ごとに使えるものが違う.

手順に書けるのは, `op`, 当てはめた値 (`state`) と, その手順の登録簿にある引数 (`register_step` の `params` に書いた鍵) だけ. 知らない引数があれば `load_recipe` で読んだ時点で, 手順と引数の名前を挙げて止める (新しい版の ML-EDA で書いたレシピを古い版で読むと, 知らない引数を無視して別の列を作り, 後の手順で分かりにくい誤りになるため). 中身の手順 (`item_steps`) も同じく, `op`, `state` と, 中身の手順の登録簿の引数 (`ItemStep.params`) だけを書け, 知らない引数は `load_recipe` で, 中身の手順の位置と名前, 引数の名前を挙げて止める (黙って無視すると, 別の配列を作るため). 引数の値に空 (None, YAML の空) は書けない. 既定を使う場合は引数を省く (`columns` や `lag` の `by` と `time` のように, 空が省いた場合と同じ意味になる引数も, 空は誤り). 表の手順と中身の手順のどちらも, 空の引数があれば `load_recipe` で読んだ時点で, 手順の位置と名前, 引数の名前を挙げて止める (読めてしまうと, 当てはめの時に `vocabulary` の `max_tokens` の `int(None)` のような分かりにくい誤りになるため). 欠けた値の行で絞る場合は, `filter_rows` の `value` を空にせず `compare: isna` を使う. 当てはめた値 (`state`) は引数でないので確かめない. `item_steps` が並びでなければ誤り. 知らない手順と種類に合わない手順は, 種類の分かる `prepare` (と `preview_items`) で止める.

```yaml
format_version: 1
target: species           # 目的の列
task: classification      # classification, regression, forecasting など
steps:
  - {op: drop_columns, columns: [id]}
  - {op: impute, columns: [age], strategy: median}
  - {op: one_hot, columns: [sex]}
  - {op: standardize, columns: auto}
split:
  method: stratified      # random, stratified (分類), time (時系列は時刻の順), group,
                          # group_time (グループと時刻の組), stratified_group (グループの層化)
  column: customer_id     # グループの列 (書かなくてよい. 下の「グループの列」)
  valid: 0.2
  test: 0.1
  seed: 0
  unlabeled: drop         # 目的の列の欠けた行. keep で unlabeled の分割に残す (下の「正解の欠けた行」)
```

- **グループの列**: `split.column` に顧客や患者の ID のような, 同じ人や物の行をまとめる列を書く. `group`, `group_time`, `stratified_group` の分割では同じ値の行を同じ分割にまとめ (新しい人に当てはめる力を測る), 他の分割のしかたでは同じ値が複数の分割にまたがるかを確かめて, `prepare` の気付き (`group_overlap`) にする (時刻の順の分割では, 同じ人が過去と未来にまたがるのは普通なので `info`, 他は `warning`. 気付きの文は, 時刻の順なら `group_time`, 層化なら `stratified_group`, 他は `group` を勧める). 分割の前の手順でこの列を落としても, 分割には落とす前の値を使う (学習に使わない ID の列で分けるため. 列が残っていれば手順をかけた後の値). 確かめには元の行の値を使い, 欠損は数えない (分割では欠損の行を 1 つのグループにまとめる). 書いた列が無ければ, 分割のしかたに依らず誤り. 問題の設定 (ML-Quest) に同じ相手の行をまとめる列があれば, ML-Quest が作るレシピの雛形がこの欄に書く
- **正解の欠けた行**: 目的の列の欠けた行は, 既定 (`split.unlabeled: drop`) では手順の前に落とす. `keep` にすると, 落とさずに `unlabeled` という名前の分割に残す (半教師あり学習や異常の検知のように, 正解の付いた行が少なく, 正解の無い行も学習に使いたい場合のため). 目的の列 (`target`) を書いていないレシピで `keep` は誤り (`load_recipe` で読んだ時点で止める. 読めても前と後の様子と書き出しの全てで止まるレシピを残さないため. データの役割だけで目的の列を決めている場合も, `keep` ではレシピに `target` を書く)
    - 正解の付いた行の前処理と分割と当てはめは, `drop` と全く同じ (`unlabeled` の行は値を学ぶ手順にも, 分割の割合と層化にも, 分割の前の手順にも入れない). 書き出す train, valid, test は `drop` の場合と同じ中身になる
    - `unlabeled` の行には, 推論のとき (`Dataset.transform`) と同じかけ方で, 学習用で当てはめた値をそのままかける (当てはめ直さない. 行を絞る手順は目的の列を見ず, 過去の値の列は推論と同じ前後関係). 推論と同じく, 重複の手順は落とさない. 行を絞る手順で落ちた行は除く. 学習に使う列はその値, 他の列 (ID など) は元の値, 目的の列は欠損. 正解の無い行の情報を前処理に入れる (正解の無い行も含めて標準化するなど) ことは今はしない (検証用とテスト用の当てはめと同じ値にそろい, 推論のときとも同じになるため)
    - 画像, 文, 点群, 音声は, `unlabeled` の件にも学習用で当てはめた中身の手順をかけ, 配列 (`unlabeled_items.npy`) にする (表の列は学習に使わないので元の値)
    - 学習に使う列の欠損が `unlabeled` の分割にだけ残る場合は注意 (`notes`) にする
    - 分割をまたぐ重なりの気付き (`group_overlap`, `item_overlap`) は正解の付いた分割だけで確かめる (同じ人の正解の無い行を学習に使うのは普通なため)
- **時刻の順の分割**: 時刻で並べた後ろの部分を検証用とテスト用にする. 件数で切った境目の時刻の行は後ろの分割にそろえ, 同じ時刻の行 (店ごとの売上の同じ日など) が学習用と検証用にまたがらないようにする
- **グループと時刻の組の分割** (`group_time`): 相手ごとの時系列で, 同じ相手を 1 つの分割にまとめつつ, 後から現れた相手を検証用とテスト用にする (新しく現れる相手に当てはめる力を, 未来の向きで測る). グループの列 (`split.column`) と日時の列が要り, どちらかが無ければ誤り. グループを最初の時刻の順に並べ (最初の時刻が同じグループは値の文字の順で, 境目では別の分割に分かれうる. 時刻の順の分割と違い, 同じ時刻をそろえるとグループの数で大きく外れるため), 行を並べた位置で件数を切り, 境目をまたぐグループは後ろの分割にそろえる (時刻の順の分割の境目の時刻と同じ. 大きなグループが境目にあると, 検証用やテスト用が割合より多くなる). 時刻の読めないグループは先頭 (学習用) に置く. 守るのは「後ろの分割の相手は, 前の分割の相手より後に現れた」ことで, グループの中の行の時刻は分割をまたいで重なりうる (長く続く相手の後半の行は, 後から現れた相手の行より後の時刻のことがある). 並べ方を最後の時刻でなく最初の時刻にするのは, 新しく現れた相手を当てる使い方 (現れた時点で予測する) に合わせるため
- **グループの層化** (`stratified_group`): 同じ相手を 1 つの分割にまとめつつ, 目的の値の割合を分割の間で近くする (少ないクラスの相手が検証用に入らないことを防ぐ). グループの列と目的の列が要る. 各グループの層は, そのグループの行で最も多い目的の値 (同じ数なら文字の小さい値. 層化の分割と同じく値を文字にそろえる). 検証用とテスト用の行の数を層の行の数に比例して配り (層化の分割と同じ最大剰余法), 層ごとに無作為に並べたグループを, 入れると配った数に近づく限りテスト用, 検証用の順に入れる (層ごとの数はグループより小さくなりやすいので, `group` と違い少し超えてもよい). 層で配り残した数と超えた数は次の層に回す (クラスが多く, 層ごとの数がグループの半分より小さい場合も, 全体で割合に近づく). 全ての層の後に全体の数に届かなければ, 学習用のグループを, 入れると全体の数に近づく順に足す (割合があるのに 0 件なら, 学習用にグループが 2 つ以上残る限り, 最も近いグループを 1 つ入れる. `split_counts` の 1 件以上の決まりと同じ). 値の混ざったグループが多いと割合は近似になる. 回帰と時系列の予測のタスクでは誤り (`load_recipe` で止める. 目的の値で層を作れないため, `group` を使う). タスクを書かない場合も, 目的の値が 20 種類より多く行の半分より多い (ほぼ全て違う) と誤り
- **グループでまとめた分割の件数の注意**: `group`, `group_time`, `stratified_group` では, 割合を書いた分割が 0 件になった場合と, 行の数が割合の数 (`split_counts`) から半分より多く外れた場合に, `prepare` の `notes` に書く (書き出すと `dataset.yaml` の `notes` に残る)
- 新しい分け方はレシピの版 1 に含む (`split.method` の値を足しただけで, この値を知らない ML-EDA は「知らない分割のしかた」で止まり, 黙って別の分け方をしないため)
- **当てはめと適用を分ける**: 平均や語彙のように, データから値を学ぶ手順 (標準化, 欠損の補完, 符号化) は, 分割した後の学習用のデータだけで当てはめ (`fit`), 同じ値を検証用とテスト用に適用する. 検証用のデータの情報が学習に漏れないように
- **分割の前にかける手順**: 値を学ぶ最初の手順より前にある手順 (列や行を落とす, 重複を落とす, 過去の値の列など) は, 分割の前に全体にかける. 分割をまたぐ重複を落とせ, 時系列の過去の値も分割の境目で切れない
- **列の決め方**: `columns: auto` は, 役割のある列 (目的の列, 日時の列, ID の列) を除いた, 手順に合う型の列. 決めた列は手順の `state.columns` に保存し, 推論のとき (`Dataset.transform`) も同じ列を使う. 推論のときは, 行を落とす手順 (重複, 欠損, 条件) も過去の値の列の前後関係を学習のときとそろえるためにかけ, 最後に入力の行の並びに戻す (重複した行は残した行と同じ値, 落とした行は欠損にし, 落とした手順を `attrs["dropped"]` で返す. 欠損の手順は目的の列を見ず, 目的の列で絞る手順は目的の列が分からない行を残す. 目的の列が分からない先の行を予測するため). 過去の値の列が目的の列を読む場合, 学習のときは目的の列が分かる行だけで前後関係を作ったので, 分かる行は分かる行だけでかけ, 分からない行は全ての行でかけた値を使う. 同じ名前の列がある表は誤りにする. 目的の列を書き換える手順は目的の列だけを除いてかける (入力と行がそろい, 同じ手順で変えた特徴量は学習のときと同じ値になるように. 除いた目的の列の欠損の印の列は 0). ただし目的の列の過去の値の列 (lag) があり, 目的の列 (過去の値) を渡した場合は, 目的の列にも学習のときと同じ手順をかける (lag が学習のときと同じ値を読むように). 過去の値の列 (lag) は目的の列を読むだけなのでかける (目的の列の過去の値を含めて渡す. 無ければ目的の列を除いてかけ, 後の手順で足りない列を誤りにする). 当てはめた列が入力に無い場合は, 手順の途中で落ちる前に列の名前を挙げて誤りにする (列を落とす手順 `drop_columns` の列は入力に無くてよい)
- カテゴリの値は, 型に依らない文字にそろえる (整数の列に欠損が入って 1 が 1.0 になっても同じカテゴリ). 欠損はカテゴリにしない
- 当てはめた値はレシピと一緒に保存し, 後から新しいデータ (推論のとき) に同じ前処理をかけられるようにする
- 手順ごとの前と後を `preview(data, recipe, upto)` で返す (GUI で 1 段ずつ確かめるため)
- 表の手順: 列を落とす, 行を絞る (`compare` で比べ方を書く), 型を変える, 欠損の補完 (平均, 中央値, 最頻値, 定数), 欠損の行を落とす, 外れ値の切り詰め, 対数, 標準化, 最小と最大の正規化, ワンホット, ラベルの番号付け, 日時の分解 (年, 月, 曜日, 時), 表記のゆれをそろえる (`normalize_text`. NFKC と前後の空白), 時系列のずらし (lag) と移動平均 (`by` で系列ごと) (lag の `columns: auto` は目的の列も選ぶ. 予測では目的の列の過去の値が最も大事な手がかりで, ずらすので未来の値は使わない). lag は既定では行でずらす. `time` (時刻の列) と `freq` (1 つ分の間隔. `1D`, `1h` など) を書くと時刻でずらす: k つ前は k × freq だけ前の時刻の同じ系列の値 (`match: previous` (既定) はその時刻が無ければそれより前で最も近い値, `exact` は無ければ欠損), 幅 w の移動平均は w × freq 前からその時刻の前までにある値の平均 (行でずらす場合と違い, 値が 1 つでもあれば欠損にしない). 移動平均は既定で 1 つ前から始まる. `gap` (1 以上の整数. 既定 1) を g にすると, g つ前から始まる幅 w の平均にする (時刻でずらす場合は [時刻 - (g - 1 + w) × freq, 時刻 - (g - 1) × freq) にある値の平均で, 休みの日などでその時刻に行が無くても, 窓に値があれば平均を出す. 列の名前は `<列>_mean<幅>_gap<g>`. 決める時点で 1 つ前の値がまだ分からない予測のため. 問題の設定の「決める時点で何期前まで分かるか」に合わせる). 系列と時刻が重なる行は, ずらした値には後の行を使い, 移動平均には全てを入れる. 時刻の読めない行は欠損. ずらす列は数値だけ. freq は長さの決まった間隔だけ (月や年は不可). 休みの日のような抜けを挟んでも, 7 つ前が暦の 7 日前 (休みなら 8 日前) になる
- 画像, 文, 点群, 音声は, 表 (1 行 1 件の様子) の手順で件を絞ってから, 中身の手順 (`item_steps`) で 1 件ずつ配列にする. 中身の手順も学習用の件だけで当てはめる (画像の正規化は学習用から無作為に選んだ最大 500 件, 語彙は学習用の全ての文). 配列は 1 件ずつファイルに書き (全てをメモリに並べない), 読むときはファイルから少しずつ読む. 全ての件の形がそろわない場合は理由付きの誤り
- `prepare(data, recipe, read_items=False)` は中身を読まずに, 中身の手順の確認 (知らない手順, 種類に合わない手順, 省けない引数, 文の vocabulary) と, 読み込みの表から分かる書き出しで失敗しそうなこと (読めない件, 大きさ, 色の形式, 点の数のばらつき, 音声の周波数とチャンネル数と長さのばらつき) を注意 (`notes`) にする. 画面の前と後の様子に使う
- **分割の後に分かる気付き**: `prepare` は分割をまたぐ重なりを, 分析の気付きと同じ形 (`{severity, code, message, columns}`) で `Prepared.findings` に返し, その文を `notes` にも足す (画面は今の注意の欄にそのまま出せ, 書き出すと `dataset.yaml` の `notes` に残る. 約束の版は変えない). 確かめるのは元の行の値 (分割の前の手順で変える前). 中身を読まない `read_items=False` でも出す
    - `group_overlap`: グループの列 (上) の同じ値が複数の分割にまたがる (またがる値の数と行の数, 例)
    - `item_overlap`: 同じ画像 (`digest` が同じ) が複数の分割にまたがる. 分割の前に `drop_duplicates` (`columns: [digest]`) で落とすよう案内する
- `preview_items(data, recipe, count, fit_limit)` は, 中身の手順を学習用の少ない見本 (既定 100 件) で当てはめ, 学習用から無作為に選んだ数件にかけた前と後を返す. 画面で手順の効き方 (大きさ, 正規化, 語の番号, 点の数, 音声の周波数と長さ) を見るため
    - 画像: `resize` (大きさをそろえる), `grayscale` (灰色), `rgb` (灰色とカラーが混ざる場合に 3 チャンネルに), `normalize` (学習用の平均と標準偏差で正規化し, (チャンネル, 高さ, 幅) に)
    - 文: `vocabulary` (学習用の文で語彙を作り, 語か文字の番号の決まった長さの並びにする. 0 は埋め草, 1 は語彙に無い語. `unit` は `char` (文字), `word` (語. 文字と数字の並び, 漢字とかなは 1 文字ずつ), `subword` (学習用の文で BPE の部分語の語彙を作る. 空白と記号で区切ってから, 1 つの部分語は 16 文字まで. `tokenizers` が要る))
    - 点群: `sample_points` (点の数をそろえる), `normalize_cloud` (中心を原点にし, 最も遠い点までを 1 にする)
    - 音声: 1 件は `samples` ((標本の数, チャンネル) の float32) と `sample_rate` の辞書で, 手順の後も同じ形. 配列にするときに (チャンネル, 標本の数) の float32 に並べ替える (PyTorch の音声の慣例の並び). どれも値を学ばない (当てはめは無い). 引数の値 (`rate` と `channels` は 1 以上の整数, `seconds` は 0 より大きい数, `method` と `align` は決まった値) は, 中身を読む前の `prepare(read_items=False)` でも確かめる. 手順は渡した順にかけるので, `resample`, `mix_channels`, `fix_length` の順に書く (`fix_length` の秒は, かけるときの周波数で標本の数にするため)
        - `resample` (`rate`: そろえる周波数, 1 以上の整数. `method`: `sinc` (既定) か `linear`): 標本化の周波数をそろえる. 同じ周波数ならそのまま. `sinc` は多相のフィルタ (元と先の周波数の比を既約の分数 up / down にし, Kaiser の窓 (beta 8.6) をかけた sinc の低域通過で, 両側 16 の零点 (下げる場合は比で広げる) の重みを up 通りの位相ごとに作り, 位相ごとに重みの和を 1 にする. 下げる場合は先の周波数の半分より高い音を落とし, 折り返しを防ぐ). `linear` は線形補間 (速いが, 下げる場合に折り返す). 標本の数は ceil (元の数 × up / down). `sinc` は端の外を 0 とする (短い音声では端の値が下がる), `linear` は最後の標本より後を最後の値とする. 位相ごとの重みは比ごとに 1 度だけ作る. numpy だけで書く (任意の依存を足さない. 多相のフィルタは numpy の窓と配列の計算で足り, 学習の入力をそろえる質には十分なため)
        - `mix_channels` (`channels`: 1 以上の整数): チャンネルの数をそろえる. 1 は全てのチャンネルの平均, 1 チャンネルの音声を 2 以上にする場合は同じ音を並べる. 同じ数ならそのまま. 他の組 (5.1 チャンネルを 2 にするなど) は混ぜ方が決まらないので, 元と先のチャンネルの数を挙げて誤り
        - `fix_length` (`seconds`: 0 より大きい数. `align`: `start` (既定) か `center`): 長さを `seconds` × 周波数 (四捨五入. 0 になる場合は 1) の標本の数にそろえる. 長い音声は切り, 短い音声は 0 (無音) で埋める. `start` は先頭を残して後ろを切るか埋め, `center` は真ん中を残して両側を切るか埋める (2 で割れない 1 つは後ろ側)
    - 領域: `resize_mask` (領域の大きさを最も近い画素でそろえる. 値を混ぜない). 版 2 の書き出しが画像の `resize` から決める手順で, 版 1 のレシピには書けない (領域の種類のデータが無いため)

## 8. 書き出し (学習との約束)

`export_dataset(data, recipe, path)` は次のディレクトリを作る.

```
<データセット>/
├── dataset.yaml        # 説明 (版, 種類, 目的の列, タスク, 列と型, 分割の件数, 元のデータ, レシピ)
├── recipe.yaml         # 当てはめた値を含むレシピ (新しいデータに同じ前処理をかけるため)
├── train.parquet       # 分割ごとのデータ (表と時系列. parquet が無い場合は csv)
├── valid.parquet
├── test.parquet
├── unlabeled.parquet   # 目的の列の欠けた行 (split.unlabeled: keep の場合だけ)
└── train_items.npy     # 画像, 文, 点群, 音声の中身の手順をかけた配列 (分割ごと. 表には無い)
```

`dataset.yaml` (版 1) の項目.

| 項目 | 中身 |
| --- | --- |
| `format_version` | 版 (1) |
| `name`, `created_at` | 名前と作った時刻 |
| `kind`, `task`, `target` | 種類, タスク, 目的の列 |
| `features` | 学習に使う列の名前と型 (目的の列は含まない) |
| `classes` | 分類のクラス (番号の順) |
| `splits` | 分割ごとのファイルと件数 (画像などは中身の配列のファイル `items` と形 `shape` も). 分割の名前は `train`, `valid`, `test` と, `split.unlabeled: keep` の場合の `unlabeled`. 件の無い分割は書かない |
| `source` | 元のデータの名前, 読み込み, 大きさと更新時刻 (下の「元の場所 (版 1)」) |
| `recipe` | 前処理のレシピ (`recipe.yaml`) |
| `notes` | 前処理の後の注意 (数値でない列が残っているなど) |

**元の場所 (版 1)** (`source`): 読み込んだデータの `source` の写しから, 手元の場所の欄 (読み込んだ場所 `path` と, ディレクトリの読み込みの 1 件の場所の基 `root`) を除く. 書き出したデータセットは人に渡すことがあり, 手元のディレクトリの構成を残さないため. 代わりに読み込んだ場所 (無ければ `root`) の名前だけ (版 2 の「元の場所」と同じ畳み方. `path` はリンクをたどった後の場所なので, その名前) を `name` に書き, `paths: name_only` と `note` (名前だけを残したこと) を添える. 場所の無い `source` (手元で作ったデータ) は場所の欄を足さない. 読み込みの名前と設定 (`loader`, `options`), 大きさと更新時刻 (`size`, `modified`) はそのまま残る. 表と時系列は, 読み込んだ表の列の名前の並び (目的の列も含む, 読んだ順) を `columns` に書く (読む側が元のデータの列を知るため. 名前だけで値は残さない. 画像, 文などは書かない). 読む側が頼ってよいのは `loader`, `options` (推論で同じ設定で読み直すため) と `columns` だけ. 元のデータを読み直す場合は, 書き出した場所に頼らず読む側が場所を持つ.

**モデルの入力** (`model_inputs(path, follow_links=False)`): 書き出したデータセット (版 1 と, ファイルの組の版 2 と 3) の説明から, モデルが受け取る入力と出す値の数を JSON にできる辞書で返す. 画面 (ML-Fathom) がデータセットの一覧で「モデルに要るもの」を見せ, モデルの定義 (ML-ModelControl の `inputs` と最後の層の出す数) をデータに合わせるため. 分割のデータは読まない (画像などの中身の配列は, 型を知るためにファイルの頭だけを読む). 版 1 で読む `dataset.yaml`, 中身の配列 (`items`), 文のレシピ (`recipe`) の場所は `load_dataset` と同じくデータセットのディレクトリの中に限る (外は誤り. 外を指すリンクは引数 `follow_links=True` でたどる. 無いファイルは `FileNotFoundError`).

| 鍵 | 中身 |
| --- | --- |
| `inputs` | 入力の並び. 1 つは `{name, shape, dtype}`. 版 1 の入力は `tensors` の特徴量 1 つだけで, 名前は `x`. 形はバッチの次元を `null` にした形 (表と時系列は `[null, 学習に使う列の数]` で `float32`. 画像, 文, 点群, 音声は中身の配列の形と型. 例: 画像は `[null, 3, 64, 64]` の `float32`, 音声は `[null, チャンネル, 標本の数]` の `float32`, 文の語の番号は `[null, 128]` の `int64`). 文の語の番号の入力は, 書き出したレシピの最後の `vocabulary` の手順の語彙の大きさ (`<pad>` と `<unk>` を含む語彙の数. 語の番号の上限 + 1) を `vocabulary` に持つ (モデルの埋め込み (`nn.Embedding` の `num_embeddings`) にそのまま使えるように. 文のデータセットだけはレシピも読む) |
| `task` | タスク (`classification`, `regression`, `forecasting`). 決めていない (`none`) 場合は `null` |
| `target` | 目的の列 (無ければ `null`) |
| `classes` | 分類のクラス (番号の順. クラスが無ければ空の並び). 分類でなければ `null` |
| `target_kind` | 正解の種類 (版 2 と 3 の `target.kind`. `mask`, `point_cloud`). 版 1 は `null` |
| `outputs` | モデルが 1 件に出す値の数. 分類はクラスの数, 回帰は 1, 時系列の予測は 1 (版 1 の説明は何期先までを持たず, 1 行に目的の値 1 つのため). タスクが無いか, 分類のクラスが無い場合は `null` |

ファイルの組 (版 2 と 3) は, 説明の `entries` の最初の入力と最初の正解の項目の種類の組から返す. `task` は `null`, `target` は正解の項目の名前, 入力の名前は入力の項目の名前. 値はどれも, ML-Quest の骨組み (ファイルの組の `train.py`) がモデルに渡す形と学ぶ数に合わせる (モデルの定義をそのまま骨組みで学習できるように).

| 組 | 入力 | `classes` と `outputs` |
| --- | --- | --- |
| 画像 (`image`) と領域 (`mask`) | `[null, チャンネル, 高さ, 幅]` の `float32` (骨組みが 0 から 1 にして (チャンネル, 高さ, 幅) に並べ替えるため). 大きさとチャンネルは項目の `shape` (書き出しが中身の手順の後の形を書く). `shape` の次元が `null` なら手順の `resize` (高さと幅) と `grayscale` (1) か `rgb` (3) から. どちらでも決まらない次元 (大きさの混ざる画像を手順なしで書き出したものなど) は `null` | `classes` は領域のクラスの名前 (値の小さい順), `outputs` はその数. 骨組みと同じ数え方で, 名前 (`classes`) があれば名前の付いた値, 無ければ値の一覧 (`values`) の全て (名前は値の文字). 名前の無い値 0 は背景 (`background`) のクラスとして足す (骨組みが背景も 1 つのクラスとして学ぶため) |
| 撮影 (`capture`) か点群 (`point_cloud`) と点群 (`point_cloud`) | `[null, 入力の点の数, 3]` の `float32`. 撮影は骨組みが深度から点に戻して選ぶので, 骨組みの config の既定 `data.input_points` と同じ 512 (`pipeline.ITEM_INPUT_POINTS`). 点群の入力は項目の `shape` の点の数がそろっていればその数, そろわなければ 512 | `classes` は `null`. `outputs` は出す点の数で, 正解の点群の項目の `shape` の点の数がそろっていればその数 (中身の手順の `sample_points` の後など), そろわなければ骨組みの config の既定 `data.target_points` と同じ 1024 (`pipeline.ITEM_TARGET_POINTS`) |

他の組 (画像と `boxes` など) は「まだ返せない」と誤りで止まる (項目の形は `dataset.yaml` の `entries` を見る). 知らない版も止まる.

`load_dataset(path, follow_links=False)` は分割ごとの `DataFrame` を返す. 読むのはデータセットのディレクトリの中だけ: `dataset.yaml`, 説明に書かれた分割のデータ (`file`), 中身の配列 (`items`), レシピ (`recipe`) の場所は, 絶対パスか `..` で外を指せば誤り (`ValueError`. 書かれた場所の文字の上で確かめる). リンクをたどった後に外 (データセットのディレクトリもたどった後の場所) を指す場合も, 引数 `follow_links=True` を案内する誤りにする (`load_items` と同じ決まり. `follow_links=True` ではたどる). 無いファイルは `FileNotFoundError`. `unlabeled` の分割の `arrays` と `tensors` は目的の値を返さない (`arrays` は y が None, `tensors` は特徴量だけ). 画像, 文, 点群, 音声では `arrays` と `tensors` が中身の配列を返し, `transform_item` で新しい 1 件に同じ中身の手順をかける. `arrays` で numpy の配列, `tensors` で PyTorch のテンソルにもできる (PyTorch が入っている場合). `transform` は新しいデータに当てはめた前処理をかける.

`load_dataset` は `recipe.yaml` も `load_recipe` と同じく確かめ, 表の手順の知らない手順と, 表の手順と中身の手順の知らない引数があれば, 手順の位置と名前, 引数の名前を挙げて止める (より新しい版の ML-EDA で書いたデータセットを読む場合に, `transform` と `transform_item` が, この版の知らない引数を黙って無視して別の値を作らないため). 空 (None) の引数は確かめない. 空の引数は, 書き出した時の当てはめと同じ読まれ方をする (`params.get(鍵, 既定)` で読む `datetime_parts` の `drop` や `vocabulary` の `lowercase` のように, 省いた場合と違う値になる引数も, 書き出した時と同じ値になる) ので, 読み込みで挙動は変わらない. 空の引数のある古い書き出しも読めるようにするため.

書き出しは, 前処理を済ませてから隣の一時ディレクトリに書き, 最後に入れ替える. 既にある場所を置き換えられるのは, 前に書き出したデータセット (`dataset.yaml` を持つもの) だけ.

版の決まりは ML-ModelControl と同じ. 項目を足す, 消す, 変える場合は版を上げ, 読む側は知っている版より新しいものを「この版は読めない」とする.

`kind` の値は, 版を上げずに増える (今は `table`, `timeseries`, `image`, `text`, `pointcloud`, `audio`). 中身の配列 (`items`) を持つ分割は, 種類に依らず `arrays` と `tensors` で同じく読める (配列の形は `shape`) ので, 学習で読むだけなら知らない種類も違わない. 読む側が種類ごとに読み方を変える場合は, 知らない種類で止める (表として読まない). 新しい 1 件に中身の手順をかける `transform_item` は, その種類の手順を持つ ML-EDA が要る (手順を持たない ML-EDA は登録簿に無い手順の名前の誤り (`KeyError`) で止まり, 黙って違う値は作らない). 版 3 (中身の手順の欄) と違い, 欄の意味は変わらず, 推論の取り違えも誤りで気付けるので, 版を上げない.

`splits` の分割の名前は版 1 の初めから決まった組ではない (検証用とテスト用の割合が 0 なら書かない) ので, 読む側は名前を指して分割を選ぶ. `unlabeled` の分割は版 1 に含む (`train`, `valid`, `test` の目的の列に欠損は無く, 正解の無い行は名前の違う分割にだけ入る. ML-Quest が作る ML-Found の学習のスクリプトの雛形, ML-Inference の一式の作成, ML-Fathom の画面は, `train`, `valid`, `test` を名前で選ぶか, 全ての分割の件数を並べて見せるだけで, 知らない名前の分割を正解のある分割として使わない). 読む側が全ての分割を正解のある分割として回す場合は, `unlabeled` を除く. レシピの `split.unlabeled` も同じ理由で版 1 に含む (この項目を知らない ML-EDA は読まず, 既定の `drop` として動く).

## 9. 書き出しの版 2 (ファイルの組とまとまり)

版 1 の約束は「1 件 = 1 行, 正解は列 1 つ」なので, 入力と正解がファイルの組 (画像と領域, 撮影と点群) のデータや, 1 件がファイルのまとまり (多視点の撮影) のデータを書けない. これらと, 受け持ちを持つ正解の無い表 (群分けの表) は版 2 の約束で書く. 版 1 で書けるものは版 1 のまま, 正解を作った処理を記録する, `task` は列の正解だけ, 書き出せる例は画像と領域の対, 撮影と点群の対と群分けの表.

- **版 1 で書けるものは版 1 のまま**: 表, 時系列と, 画像, 文, 点群, 音声の列の正解 (クラスか値) は, `export_dataset` が版 1 で書く. 版 2 を書くのは, 正解がファイルのものとまとまりのもの (`export_image_masks` と `export_capture_clouds`) と, 受け持ちが群分けの表 (`export_group_rows`) だけ. 版 1 しか知らない今の読む側を壊さないため
- **読む側の止まり方**: `load_dataset` (版 1 の読み込み) は版 2 を見ると「ファイルの組のデータセットなので `load_items` で読む」と言って止まる. `load_items` は版 1 を見ると `load_dataset` へ案内して止まる. 知らない版 (3 以上) はどちらも「この版は読めない」と止まる
- `pipeline.DATASET_FORMAT_VERSION` は版 1 (`load_dataset` が読む版) のまま変えない. ML-Inference がデータセットの写しの版の確かめに使っていて, 2 に上げると版 2 を版 1 として通してしまうため. 版 2 の番号は `pipeline.ITEMS_FORMAT_VERSION` (`items` からも使う)
- **版 3**: 版 2 に, 項目ごとの中身の手順 (`entries.<名前>.steps`. 下の「中身の手順」) を足した版. 中身の手順を渡した書き出しだけが版 3 で書き, 渡さない書き出しは今までと同じ版 2 で書く (手順の無いデータセットを版 2 しか知らない読む側が読めるように). 版を上げるのは, この欄を知らない読む側が推論で新しい 1 件に手順をかけず, 大きさの違う入力を黙ってモデルに渡すため (データセットの中のファイルは手順をかけた後なので, 学習で読むだけなら違わないが, 推論の取り違えは気付けない). 版 3 の番号は `pipeline.ITEMS_STEPS_FORMAT_VERSION`, `load_items` が読む版の組は `pipeline.ITEMS_FORMAT_VERSIONS` ((2, 3)). `ITEMS_FORMAT_VERSION` は 2 のまま (版 2 の番号として読む側が使っているため). 他の欄の意味は版 2 と同じ

```
<データセット>/
├── dataset.yaml         # 説明 (版 2)
├── items.parquet        # 1 行が 1 件の表 (parquet が無い場合は csv)
└── items/
    ├── 000000/          # 1 件のファイル (番号は表の行の順)
    │   ├── image.png
    │   └── mask.png
    └── 000001/
```

### 版 2 の説明 (`dataset.yaml`)

**正解の出どころ** (`target.origin`). 正解が外の処理の出力の場合も, 何で作ったかは問わずに「入力のファイル群」と「正解のファイル」の組として受け取り, 作った処理を書いておく.

- `type`: `process` (今ある処理の出力), `annotation` (人が付けた), `measurement` (測った), `synthetic` (作った正確な正解), `unknown` (渡されていない. 既定)
- `name`, `settings`: 正解を作った処理 (か道具) の名前と設定
- `process` の場合, 正解はその処理の出力なので, 測れるのは「その処理との一致」で, モデルはその処理を超えられない. 後の段階 (ML-Found の評価, ML-Inference の結論) はこの欄を読んでそう書く. `annotation` も付けた人との一致

**分割**: 版 1 と同じく 1 件ごと. `random` (既定), `group`, `none` (全て学習用. 説明の `valid` と `test` は 0). `groups` (件の `id` からグループ) を渡すと既定は `group` で, 同じグループの件を同じ分割にまとめる (撮影は現場や物で分ける). 他の分け方でグループが複数の分割にまたがると, `group_overlap` と同じ注意を `notes` に書く. `groups` に無い `id` は誤り. 割合を指定した分割が 0 件になった場合 (グループが割合に収まらないなど) も `notes` に書く. `stratified` と `time` は今は誤り (正解がファイルなので層が無い. 時刻は件の表に時刻の列を持ってから).

**正解の無い件** (`split.unlabeled`): 既定 (`drop`) では, 正解のファイルの無い入力 (領域の無い画像, 点群の無い撮影) を除き, 数と例を `notes` に書く. `keep` にすると, 除かずに `unlabeled` という名前の分割に書く (版 1 の `split.unlabeled: keep` に当たる. 半教師ありの学習や, 推論の確かめに使えるように). `drop` と `keep` の他は誤り.

- 正解の付いた件の分割と中身は `drop` と全く同じ (`unlabeled` の件は分割の割合にもグループの重なりの確かめにも入れない). 表では正解の付いた件の後ろに `id` の順で続け, 正解の付いた件の番号 (`items/000000` など) も `drop` と同じ
- 入力は正解の付いた件と同じに書く (画像は同じ確かめ (読めるか, EXIF の向き. 後から正解を付け足すときに画素がずれないように) と同じ中身の手順, 撮影は同じ正規化と手順. 平行移動の列も持つ). 正解の項目の列は空 (null). 入力の項目の `shape` と `formats` は `unlabeled` の件も含めて求め, 正解の項目の `shape`, `values` などは正解の付いた件だけで求める
- `groups` は `unlabeled` の件には無くてよい (分割に使わないため. 無ければ `group` は空)
- 入力の無い正解 (画像の無い領域, 撮影の無い点群) は, `keep` でも除いて `notes` に書く
- 版は変えない (版 2 のまま. 中身の手順を渡せば版 3). 版 1 と同じく, 分割の名前は決まった組ではないので, 読む側は名前を指して分割を選ぶ (ML-Quest の骨組みは `train`, `valid`, `test` を名前で選び, ML-Inference の推論は入力の項目だけを読む). 全ての分割を正解のある分割として回す読む側は, `unlabeled` を除く. この欄を知らない ML-EDA は `split.unlabeled` を読まず, 今までと同じく除く

**前処理**: 中身の手順を渡さなければ, ファイルをそのまま写す (撮影と点群は座標の正規化だけ). 渡すと, 項目ごとに手順をかけたファイルを書く (下の「中身の手順」).

### 群分けの表 (`export_group_rows`)

`export_group_rows(source, path, columns, id=None, split=None, name=None, overwrite=False, loader=None, **options)` は, 群分け (まとめる) の 1 行が 1 つの対象の表を版 2 のデータセットに書く. 正解が無く受け持ちが群分けなので, 版 1 (`task: none`) ではなく `role` を持つ版 2 で書く. ファイルは `dataset.yaml` と件の表 (`items.parquet` か `items.csv`) だけで, `items/` のディレクトリは作らない.

- `source` と列の決まりは「群の要約」と同じ (表のファイルか表の `Data`. 群を作る列の名前の誤りも同じ). `id` は行を見分ける列 (群を作る列に入れると誤り. 欠けか同じ値があれば誤り). 省くと行の位置 (0 から) の文字を件の `id` にする. `columns` と `id` の他の列は書かない
- 項目: 群を作る列ごとに 1 つ (名前は列の名前の文字. `role: input`, `placement: column`). 数の列 (真偽値を除く) は `kind: value` で, `dtype` は書いた型 (`int64`, `float64` など. pandas の欠けを持てる型は `float64` にして書く). 他の列は `kind: class` で, 値を文字にし (欠けは欠けのまま), `dtype: str`. 値は件の表の同じ名前の列に置く
- `role: group`, `target: {kind: none, entries: []}` (正解は無い. `origin` は書かない)
- 分割: 版 2 と同じ `random` (既定. 検証用 2 割, 種 0) か `none`. `group` は誤り (グループの列を持たないため). 群分けの学習のスクリプトは検証用の行で群のまとまりを測る
- `source`: 版 1 の「元の場所 (版 1)」と同じ畳み方 (場所は名前だけ, 読み込みの名前と設定, 大きさと更新時刻, 読んだ表の列の名前) に, 行を見分ける列の名前 `id` (無ければ None) を足す
- `notes`: 群を作る列に欠けた値のある行の数と, 行の数の半分より多い種類の値を持つ他の列 (行を見分ける列のように群を作る力が無い)
- 読み込み: `load_items` で読む. 1 件は `id`, `split`, `group` (None) と列ごとの値. `items.csv` では欠けた値が空の文字になるので, `load_items` は列の値の項目 (`placement: column`) のうち, `dtype` が数の型のものを数に (空と数にならない文字は欠け), 他のものを文字のまま (空は欠け) 読む. csv では欠けと空の文字を見分けられないので, 空の文字の値は欠けとして読む (parquet では空の文字のまま). `describe_groups(読んだデータセット, k=...)` で群の要約も求められる
- `model_inputs` は群分けの表を受け付けない (入力 `value` か `class` と正解無しの組は, 知らない組の誤り. 符号化した行の幅は種類の列の値と学習用の行で決まり, 説明だけでは決まらないため)

### 中身の手順 (`item_steps`)

書き出し (`export_image_masks`, `export_capture_clouds`) の `item_steps` に, 項目の名前から手順の並び (版 1 の `item_steps` と同じ登録簿の手順と同じ書き方. `{op: resize, width: 64, height: 64}` など) の辞書を渡すと, 1 件ずつ手順をかけたファイルを書き, かけた手順を項目の `steps` に残す (版 3). 大きさをそろえるなどを学習のコードで毎回書かず, 推論でも同じ手順をかけられるようにするため.

- **ファイルに残せる手順だけ**: 手順はファイルにかけて書くので, かけた後もその項目のファイルの形 (8 bit の画像, 領域, 点群) に収まる手順だけを使える. 項目ごとに使えるものは下の表. 他の手順 (画像の `normalize` は値が小数の (チャンネル, 高さ, 幅) になり, 点群の `normalize_cloud` は実寸と正規化の平行移動を壊し, 推論で元の大きさに戻せない) は誤り. 値を学ぶ手順 (`fit` のあるもの) は今は使えないので, `steps` は当てはめた値 (`state`) を持たない
- **引数**: 手順の登録簿にある引数だけ. 知らない引数は手順と引数の名前を挙げて誤り (黙って無視して違うファイルを書かないため). 大きさと点の数は 1 以上の整数
- **書いた手順**: 手順は渡した順にかける. `steps` には `op` と引数だけを書く (`{op: resize, width: 64, height: 64}`)
- **読み込み**: データセットのファイルは手順をかけた後なので, `load_items` は手順をかけずに読む. 項目の `shape` と `dtype` は手順をかけた後のもの
- **推論**: 新しい 1 件に同じ手順をかけるには, 画像, 領域, 点群は `transform_entry(データセット, 項目の名前, 中身)`, 撮影は `normalize_capture(撮影, 写す先, steps=項目の steps)` を使う (下の「推論のときの読み方」). 読む側の知らない手順 (新しい ML-EDA で足した手順) は, 手順の名前を挙げて誤りで止まる

| 項目 | 使える手順 | かけ方 |
| --- | --- | --- |
| 画像 (`export_image_masks` の `image`) | `resize`, `grayscale`, `rgb` | `read_image` で読んだ配列にかけ, PNG で書く (拡張子は `.png`). 領域の手順は書き出しが決める. 画像の `resize` ごとに, 同じ大きさの `resize_mask` (最も近い画素. 領域の値を混ぜない) を領域の `steps` に書く (画像と領域の画素がずれないように). `item_steps` に `mask` を渡すと誤り |
| 撮影 (`export_capture_clouds` の `capture`) | `resize`, `grayscale`, `rgb` | 各枚の画像にかけ, PNG で書く (`file_path` を `.png` に直す). `resize` では, 生の深度, 穴を埋めた深度, 信頼度を最も近い画素で, 画像と同じ倍率に (深度の値を混ぜない. 深度の画像の大きさが画像と違う撮影も, 比を保つ), 内部パラメータ (`fl_x`, `fl_y`, `cx`, `cy`, `w`, `h`. 枚ごとにあれば枚ごとも) を同じ倍率に直す. `cx` と `cy` は画素の中心 (`pixel_center`) を保って写す (`pixel_center` が 0.5 なら倍率をかけるだけ). 1 つの撮影の画像の大きさがそろわなければ誤り |
| 正解の点群 (`export_capture_clouds` の `cloud`) | `sample_points` | 単位をそろえ, 正規化の平行移動をかけた後の点群にかける (色は残し, 法線は落とす) |

書き出しは版 1 と同じく, 隣の一時ディレクトリに書いてから入れ替える. 既にある場所を置き換えられるのは, 前に書き出したデータセット (版に依らず `dataset.yaml` を持つもの) だけ.

**元の場所** (`source`): 書き出したデータセットは人に渡すことがあるので, 手元のディレクトリの構成を残さない. 入力と正解のディレクトリは渡した場所の名前 (`.` と `..` を畳んだ最後の部分. シンボリックリンクはたどらない. `~` だけと根は空) だけを書き (`images`, `masks` や `captures`, `clouds`), `paths: name_only` と `note` (名前だけを残したこと) を添える. 絶対パスもデータセットからの相対の場所も書かない (相対の場所も `../../` から手元の構成が分かるため). 読む側は `source` を読まない.

### 画像と領域の対 (`export_image_masks`)

`export_image_masks(images, masks, path, split=None, groups=None, classes=None, origin=None, name=None, overwrite=False, mask_suffix="", item_steps=None, follow_links=False)`. Pillow が要る.

- 画像と領域のディレクトリの中の, リンクをたどった後にそのディレクトリ (それ自体もたどった後の場所) の外を指すファイルは写さず, 除いた数と例と引数 `follow_links=True` の案内を `notes` に書く (4 章の「外を指すリンク」). `follow_links=True` ではたどって写す

- 画像のディレクトリと領域のディレクトリ (それぞれ 2 階層まで) のファイルを, 名前の stem で組にする. `mask_suffix` (`_mask` など) を渡すと, 領域の stem の終わりからその文字を除いて組にする (`a.png` と `a_mask.png`). 1 つのディレクトリに同じ stem が 2 つあれば誤り (どれを組にするか決まらない). 片方にしか無いものは除き, 数と例を `notes` に書く
- 領域は 1 チャンネルの整数の画像 (`L`, `P` (パレットの番号), `1`, `I;16`, `I`). カラーの領域 (`RGB` など) は誤り (色とクラスの対応を決めていないため). 画像と領域の大きさの違う組は誤り. JPEG の領域は値が崩れるので注意に書く. EXIF の向き (1 以外) の付いた画像は誤り (画像は読むときに向きを直すが, 領域は直さないので画素がずれる. 領域をどちらの向きで塗ったかは書き出しでは分からないので, 黙って回さず, 向きを直して保存した画像とそれに合わせた領域を渡してもらう)
- 中身の手順 (`item_steps` の `image`) をかけると, 画像と領域を PNG で書く (領域は 8 bit か 16 bit の灰色. 値はそのまま). 領域の値が 0 から 65535 に収まらなければ誤り
- 項目: `image` (`kind: image`, 入力, `shape` は (高さ, 幅, チャンネル). チャンネル数は `read_image` で読んだ配列のもの (灰色は 1, 透明のある色は 4, 他の色は 3)), `mask` (`kind: mask`, 正解, `shape` は (高さ, 幅), `values` は全ての領域に出る値 (256 種類まで), `classes` は値の名前 (渡した場合. 値から名前の辞書 (整数の文字の鍵も) か名前の並び))
- `role: predict`, `target.kind: mask`

### 撮影と点群の対 (`export_capture_clouds`)

`export_capture_clouds(captures, clouds, path, split=None, groups=None, origin=None, cloud_units="meter", name=None, overwrite=False, item_steps=None, follow_links=False)`. 中身の手順は `item_steps` の `capture` と `cloud` (上の「中身の手順」).

- 外を指すリンク (4 章): 撮影は多視点の撮影の読み込みと同じく, 渡した `captures` と比べる (外を指す撮影と `transforms.json` は読めない撮影として除く. 撮影の中の各枚のファイルと撮影の点群は無いものとして除く). 点群のディレクトリの外を指す正解の点群は組にせず, 数と例と引数 `follow_links=True` の案内を `notes` に書く. `follow_links=True` ではたどって写す

- 多視点の撮影 (上の「多視点の撮影」の読み込みで読めるもの) と, 点群のディレクトリの直下の `<撮影のディレクトリの名前>.<拡張子>` (点群の読み込みと同じ形式) を組にする. 読めない撮影と, 片方にしか無いものは除き, `notes` に書く. 姿勢が 1 つも無い撮影, 画像のある枚が 1 つも無い撮影, 読めない正解の点群があると, 書き出し全体を誤りにする (正解の組を黙って減らさないため)
- **正規化**: 1 件ごとに, 撮影の姿勢と正解の点群に同じ平行移動をかけ, 撮った物の中心 (書き出しで残す枚 (画像のある枚) のうち, 追跡できた枚の視線に最も近い点. 方位の隙間と同じ求め方. 決まらなければカメラの位置の平均. 追跡できた枚が無ければ残す枚の全ての姿勢で) を原点にする. 書き出した撮影から中心を求め直すと原点になる. 回転と拡大縮小はかけない (実寸 (メートル) と上の向きを残す. 寸法を測るため). 中心は入力 (姿勢) だけから決め, 正解の点群からは決めない (推論のときに同じ正規化をかけられ, 正解の位置が入力に漏れないように). 足した量を表の `shift_x`, `shift_y`, `shift_z` に残し (正規化した座標 = 元の座標 + shift), `normalization` に方法, 単位, かけた項目, 列を書く. 推論のときは, 同じ正規化を `capture_shift(撮影, follow_links=False)` (足す量を求める) と `normalize_capture(撮影, 写す先, steps=None, follow_links=False)` (写して姿勢と撮影の点群に足す) でかけ (どちらも `read_capture` と同じく, リンクをたどった後に撮影のディレクトリの外を指す枚のファイルと撮影の点群は無いものとし, `transforms.json` が外なら引数 `follow_links=True` を案内する誤り), 出力を元の座標に戻すには shift を引く
- 撮影は写し直す: 各枚の画像, 生の深度, 穴を埋めた深度, 信頼度を同じ相対の場所に写し, `transforms.json` の姿勢を正規化して書く (深度はカメラから見た値なので変わらない). 他の欄はそのまま写すので, 世界の座標を持つ他の欄 (物の範囲など) には平行移動がかからない. 撮影の外を指すか無いファイルの欄は除く. 画像の無い (か外を指すリンクの) 枚は除く. 撮影が持つ点群 (`point_cloud.file_path`) も同じ平行移動をかけて PLY で書く (無いか撮影の外を指すか読めなければ除いて `notes` に)
- 正解の点群は `cloud_units` (`meter`, `centimeter`, `millimeter`) からメートルにそろえ, 2 進の PLY (x, y, z は float32. 色と法線があれば残す) で書く. 撮影の姿勢の単位はメートルとする
- 項目: `capture` (`kind: capture`, 入力, `placement: directory`, `shape` は (枚数, 高さ, 幅), `convention` は撮影の座標の決まり (下)), `cloud` (`kind: point_cloud`, 正解, `shape` は (点の数, 3), 単位はメートル, 座標は撮影の正規化した世界)
- `role: predict`, `target.kind: point_cloud`

**撮影の座標の決まり** (`entries.capture.convention`). 深度から点に戻すのに要るものを全て書く.

| 欄 | 中身 |
| --- | --- |
| `pose` | `camera_to_world` (`transform_matrix` はカメラから世界への 4 x 4) |
| `camera_axes` | カメラの軸 (撮影の `coordinate_convention.camera_axes`. 無ければ `OpenGL (+X right, +Y up, -Z forward)`) |
| `world_up` | 世界の上の向き (撮影の `coordinate_convention.world_up`. 無ければ null) |
| `origin` | `normalization` (正規化した世界) |
| `depth` | 深度の測り方. `z` はカメラの前の向きの軸に沿った距離 (光線に沿った距離ではない). `ray` は光線に沿った距離 |
| `pixel_center` | 画素の中心の位置. `0.5` は, 行 r, 列 c の画素の中心を (c + 0.5, r + 0.5) とする (`cx`, `cy` と同じ画素の座標. 左上の画素の左上の角が (0, 0)) |

`depth` と `pixel_center` は撮影の `coordinate_convention` に書かれていればそれを写し, 無ければ (null も) `z` と `0.5` とし, 書かれていない撮影の数と例を `notes` に書く. `depth` が `z` と `ray` のどちらでもないか, `pixel_center` が数でない撮影は誤り (`read_capture` も. 黙って読み違えないため). 撮影ごとの違いは既定を足してから比べる. 合成の見本 (`synthetic.render_view`) は画素の中心 (+0.5) を通る光線を, カメラの前の軸に 1 進む向き (OpenGL なら z 成分が -1) で当て, 当たった倍数を深度にするので, 深度は `z` で画素の中心は `0.5`. 見本の `transforms.json` にもそう書く. 多視点の撮影の読み込みと `read_capture` は深度の値を変えずに返す (単位をメートルにそろえ, 欠けを 0 にするだけ). OpenGL の軸で深度 d の画素 (r, c) は, カメラの座標で ((c + 0.5 - cx) / fl_x * d, -(r + 0.5 - cy) / fl_y * d, -d) になり, 姿勢をかけると世界の座標になる.

`depth` と `pixel_center` は版 2 の `convention` の欄 (他の欄の意味は変えず, この欄を知らない読む側は読まない. 無い説明は `z` と `0.5` として読む).

**推論のときの読み方**: 新しい撮影は `normalize_capture(撮影, 写す先, steps=None)` で学習と同じ正規化をかけ, `read_capture(写す先)` で `load_items` の撮影と同じ形の辞書に読む (リンクをたどった後に撮影のディレクトリの外を指す枚のファイルは無いものとし, `transforms.json` が外なら引数 `follow_links=True` を案内する誤り. `follow_links=True` ではたどる). 書き出しで中身の手順をかけたデータセット (版 3) では, `steps` に撮影の項目の `steps` を渡して同じ手順もかける. 正解と同じ形の点群は `read_cloud(ファイル)` で読む (`points` ((点の数, 3) の float64. 単位は元のファイルのまま), `colors`, `normals`). どれも `ml_eda` から使える.

### 新しい 1 件への手順 (`transform_entry`)

`transform_entry(dataset, name, value)` は, データセット (`load_items` の `ItemDataset`, `dataset.yaml` の中身の辞書, データセットのディレクトリのどれか) の項目 `name` に残した手順を, 新しい 1 件にかけ, `load_items` がその項目に返すのと同じ形で返す (推論のときに, 書き出しと同じ手順をかけるため. 版 1 の `transform_item` に当たる).

- `value`: 画像と領域はファイルの場所か配列 (画像は `read_image`, 領域は `read_mask` と同じ読み方), 点群はファイルの場所, (点の数, 3) の配列か `points` を持つ辞書
- 返すもの: 画像は (高さ, 幅, チャンネル) の uint8, 領域は説明の `dtype` の (高さ, 幅), 点群は (点の数, 3) の float32. 手順の無い項目 (版 2 も) はそのまま同じ形で返す
- 撮影は誤りにして `normalize_capture` へ案内する (撮影は写してから手順をかけ, 正規化の平行移動も要るため)
- 点群は手順だけをかける (書き出しの単位の換算と正規化の平行移動はかけない. 正解の点群は推論の入力ではないので, 新しい正解と比べるときに使う)

### 読み込み (`load_items`)

`load_items(path, follow_links=False)` は版 2 と 3 のデータセットを読み, `ItemDataset` を返す. `info` (説明), `items` (表), `entries` (項目), `split(name, read=True)` (分割の件の並び. `len` と番号で 1 件を返すので, PyTorch の `Dataset` にそのまま包める).

- 1 件は辞書 (`id`, `group`, `split` と, 項目の名前から中身). 項目の名前に `id`, `split`, `group` は使えない (書き出しと `load_items` で誤り)
- `read=True`: `image` は (高さ, 幅, チャンネル) の uint8, `mask` は (高さ, 幅) の整数 (説明の `dtype`), `point_cloud` は (点の数, 3) の float32, `capture` は `intrinsics`, `poses` ((枚数, 4, 4). 無い姿勢は NaN), `images` ((枚数, 高さ, 幅, チャンネル) の uint8), `depth` ((枚数, 高さ, 幅) の float32, メートル, 欠けは 0. 全ての枚に深度がある場合だけ, 無ければ None), `confidence` (同じく uint8 か None), `tracking`, `convention` (撮影の `coordinate_convention` に, 無ければ `depth: z` と `pixel_center: 0.5` を足したもの) の辞書. 画像の大きさがそろわない撮影は誤り
- 返す配列は全て書き込める (`writeable` が True. 種類によらず同じ). Pillow の画像から作った配列は書き込めないので写して返す (そのまま `torch.from_numpy` に渡すと PyTorch が警告を出すため)
- `read=False`: ファイルとディレクトリの場所 (絶対パスの文字)
- `unlabeled` の分割の件の正解の項目は, `read` に依らず None (表の場所が空). 他の分割の件か入力の項目の場所が空なら, 件と項目の名前を挙げて誤り (壊れた表を黙って読まない)
- 知らない `kind` の項目は場所を返す. 知らない `placement` は誤り (読み方が分からないので黙って読み違えない)
- 表の場所はデータセットのディレクトリの中だけ (絶対パスや `..` は誤り. 書かれた場所の文字の上で確かめる). リンクをたどった後にデータセットのディレクトリ (それ自体もたどった後の場所) の外を指す場所も, 1 件を読むときに理由付きの誤りにする (撮影の項目の中の各枚は無いものとし, 撮影の `transforms.json` が外なら誤り). `dataset.yaml` と表のファイルが外を指す場合は `load_items` が誤りにする. ディレクトリの読み込みと同じ決まりで, `load_items(path, follow_links=True)` ではたどる. 誤りの文は引数 `follow_links=True` を案内する

### 合成の見本 (`ml_eda.synthetic`)

道具の確かめ用 (テストで使う. ML_tester の例でも使う). ml_eda の他は numpy と標準ライブラリだけで書く (PNG も自前で書くので Pillow も描く道具も要らない).

- `write_image_masks(root, count, size, seed, sizes)`: 雑音の上に円か四角を 1 つ置いた画像と, その領域 (0 が背景, 1 が円, 2 が四角) を `images/` と `masks/` に書く. `sizes` に (高さ, 幅) の並びを渡すと, 件ごとに順に繰り返した大きさで書く (大きさの混ざった見本. 書き出しの `resize` の確かめに使う)
- `write_shape_captures(root, shapes, views, size, points, seed, count)`: 球と箱の正確な点群 (面の上の一様な点) を `clouds/<名前>.ply` に書き, 物の周りの決まった姿勢から光線を当てて (解析的な交わり) 画像, 深度 (ミリの 16 bit の PNG), 信頼度を求め, 多視点の撮影の形で `captures/<名前>/` に書く. `shapes` を省くと既定の球 2 つと箱 2 つ. `count` を渡すと, `seed` から球か箱を `count` 個ばらつかせて作る (名前は `shape_000` から. 種類, 中心 (原点から水平に 0.5 から 1.5 m, 高さ 0.05 から 0.3 m), 大きさ (球の半径 0.08 から 0.18 m, 箱の各辺 0.1 から 0.3 m), 色が乱数. 1 つの撮影には 1 つの形だけが写るので, 中心の位置は正規化の平行移動にだけ効く. `shapes` と同時には渡せない. `count` は 1 以上の整数). `transforms.json` の `coordinate_convention` に `depth: z` と `pixel_center: 0.5` を書く

### 他の型を版 2 で書く形

版 2 が 2 つの例だけに合う形になっていないかの見本として, 次の 2 つの書き方を示す. どちらも書き出しと読み込みは無く, 足すときの形の見本.

- **検出 (物の箱)**: 項目 `image` (`file`, 入力) と `boxes` (`kind: boxes`, 正解, `placement: file`, `items/{index:06d}/boxes.json` に `[{box: [x1, y1, x2, y2], class: 0}]` の並び, `formats: [json]`, `units: pixel`, `convention: {origin: top_left, axes: [x, y], box: xyxy, edges: pixel_corner}` (x が列で, 画像の `axes: [row, column]` と順が逆なので明示する), `classes`, `shape: [null, 4]` (箱の数は件ごとに違い, 物の無い画像は空の並び)). `role: predict`, `target.kind: boxes`. 今の欄だけで書ける. 今の読み込みは知らない `kind` の場所を返す
- **並べる (利用者 × 品)**: 1 件 = 見せた 1 回. 項目 `user` と `item` (`kind: id`, `placement: column`), `clicked` (`kind: value`, 正解, `column`. クリックの 0 か 1 を関連度と見なす), 要求をまとめる列 `query` (`kind: id`, `column`. 要求ごとに並べて測るため). `role: rank`, `target.kind: relevance`. 同じ要求の件が複数の分割に分かれると要求ごとの順位を測れないので, `query` か利用者をグループにし, 並べるで `random` の分割は誤りにする. 利用者と品の特徴は件の表に並べず別の表を引く置き方 `lookup` (`table: users.parquet`, `key: user`) が要る. 分割は時刻で全体を切る (利用者ごとに最後を残すと他の人の未来が入る) か利用者で `group`. 今の読む側は知らない置き方 (`placement`) で止まるので, 黙って読み違えない

## 10. 安全

- 読み込みは手元のファイルだけ. ネットワークは使わない
- 記録した軌跡 (`load_trajectory`) は, 表と説明の普通のファイルだけを読む. シンボリックリンクは辿らず, FIFO などは待たずに誤りにし, 表は 64 MiB (Parquet は 400 万行), 説明は 1 MiB を超えるものを読まない (5 章の「記録した軌跡」)
- 並べるの反応の表 (`load_reactions`), 群分けの表の書き出し (`export_group_rows`) と群の要約 (`describe_groups`) は `load_data` で読み, 読み込みと同じ決まりに従う (`Data` を渡した場合は読み直さない)
- 読み込んだディレクトリの外を指すシンボリックリンクは, 画像, 文, 点群, 撮影, 音声のディレクトリの読み込みとその `load_item`, `load_items`, `read_capture`, 版 2 の書き出し (`export_image_masks`, `export_capture_clouds`), `normalize_capture`, `capture_shift` では既定で読まない (4 章の「外を指すリンク」. 読み込みの設定 `follow_links` か, 関数の引数 `follow_links=True` でたどる)
- `pickle` を使う形式 (`.pkl`, `allow_pickle` の `.npy`) は読まない (任意のコードを動かせるため)
- 書き出したデータセットの読み込み (`load_dataset`, `model_inputs` の版 1, `load_items`) は, 説明と表に書かれた場所をデータセットのディレクトリの中に限る (8 章と 9 章. 絶対パスと `..` は誤り. 外を指すリンクは `follow_links` でたどる)

## 11. 課題の型への広げ方

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる. 版 1 の約束は「1 件 = 1 行, 正解は列 1 つ」で, ファイルの組とまとまりは版 2 で書く (上の「書き出しの版 2」). 広げる順は, 約束 (ファイルの形の版) を変えずに出せるもの → 約束の版を上げるもの → 型ごとの通り道.

- 型を足すときは, その型の分割の落とし穴を気付きにする: 推薦は時刻で全体を切る (利用者ごとに最後を残すと他の人の未来が入る), 効果は処置の後に決まる列と重なり (傾向が 0 か 1 に近い人), 自己教師はコーパスとテスト用の重なり, 撮影は現場や物で分ける
